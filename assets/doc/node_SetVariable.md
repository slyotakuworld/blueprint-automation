# 📦 SetVariable · 设置变量

> 存变量用的小盒子~每行写 名字=值，还能塞别的变量进去算一算，存好了后面所有节点都能拿来用哟。

---

## 节点外观

- **分类**：🧠 逻辑
- **配色**：深灰+粉 (#2D333B / #F778BA)
- **短名**：`set_var`

---

## 端口

### 输入
| 名称 | 类型 | 标签 | 说明 |
|------|------|------|------|
| `in_exec` | ▶ 执行 | ▶ | 上游触发 |
| `in_0`、`in_1`… | ○ 数据 | #1 输入、#2 输入… | 动态数据输入端口（最多 20 个），通过 `num_data_inputs` 调整数量 |

### 输出
| 名称 | 类型 | 标签 | 说明 |
|------|------|------|------|
| `out_exec` | ▶ 执行 | ▶ | 设置完所有变量后触发下游 |
| 变量名（如 `a`、`hp`） | ○ 数据 | 变量名 | **每个变量一个数据出口**：端口名和标签就是变量名，执行时输出「本次刚设置的那个值」。可直接连到「组件」节点的入参端口，或组件蓝图里「结束」节点的返回值端口。 |

> 数据出口是**按 `batch_text` 里写了哪些变量自动长出来的**（写几个变量就几个出参，最多 20 个），改完文本约半秒后刷新一次。
> 与执行出口 `out_exec` 重名的变量不会生成数据出口。

---

## 参数一览

| 参数名 | 编辑器 | 默认值 | 必填 | 说明 |
|--------|--------|--------|------|------|
| `num_data_inputs` | 整数 | `0` | - | 数据输入端口数（0 ~ 20）；改了以后左侧会出现对应数量的绿色端口 |
| `batch_text` | 多行文本 | `""` | - | 批量设置区，每行 `name = value`，支持变量插值和表达式 |

---

## 批量设置语法

### ① 字面量赋值
```
# 数字
hp = 100
count = 0

# 字符串（加不加引号都行，加了引号会连同引号一起存进去！）
user = Alice
hero = "贤狼赫萝"    ← ⚠ 值会包括引号："贤狼赫萝"，不是 贤狼赫萝

# 布尔
is_open = true
flag = false
```

> ⚠ **非常重要**：SetVariable 里 `name = "苹果"`，引号**不会被剥掉**，会作为值的一部分存起来！如果不想要引号，直接写 `name = 苹果`。

### ② 引用其他变量 / 输入端口值
```
# 先连一个 Command.stdout 到 in_0 端口，再：
cmd_out = {__INPUTS__0}      ← 第1个数据端口的值
py_ret  = {__INPUTS__1}      ← 第2个数据端口的值

# 引用其他 SetVariable 节点之前设置的变量
final = {hp} + {bonus}
```

### ③ 表达式计算 `{= 表达式}`
```
# 算术
total = {= {hp} + {bonus}}
double = {= {count} * 2}

# 文本拼接
full_name = {= "{first}_{last}"}

# 端口值做计算（Command.stdout 是 str，要先转 int！）
sum = {= int({__INPUTS__0}) + int({__INPUTS__1})}
```

### ④ 注释
```
# 这一行以 # 开头，是注释
// 双斜线也是注释
```

### ⑤ 变量名写法（写不对就没有数据出口）

| 规则 | 说明 |
|---|---|
| 开头 | **字母 / 下划线 / 汉字**都可以（`a`、`_tmp`、`hp`、`血量`） |
| 后续 | 字母 / 数字 / 下划线 / 汉字 |
| 点号 | 允许，如 `target.hwnd`（点号访问交给变量引擎解析） |
| ❌ 不能用 | 横杠（`my-var`）、数字开头（`1a`）、变量名里带空格 |
| ❌ 不能用 | `out_exec`（那是本节点的执行出口，重名不生成数据出口） |

> 汉字变量名可以和插值混用，例如 `血量 = 100` 之后，别的节点里写 `{血量}` 取用。
> 全角 `＝` 不行（要用英文输入法的半角 `=`）——「检查格式」会直接告诉你是全角符号。

> ⚠ **写错的行不会报错、但也不会生效**：那一行既不会变成变量，**也不会生成右侧数据出口**。
> 所以「明明写了变量，画布右边却没有 ○」基本就是这一行的名字/格式不对。
> 三处能看到原因：画布上该行会标 `⚠` 并汇总一行 `⚠ N 行不出出参`、
> 属性面板的「✓ 检查格式」按钮会指出**具体哪一行**、运行前校验与运行日志也会 WARN 一次。

## 临时输入端口变量说明

当 `num_data_inputs = N`（比如 3）时，SetVariable 左侧多出 `in_0`、`in_1`、`in_2` 3 个绿色端口。

在 batch_text 里就这一种写法引用它们：
```
__INPUTS__     = 完整数组，list 类型
__INPUTS__[0]  = 第1个端口值
__INPUTS__0    = 第1个端口值（简写，推荐）
__INPUTS__1    = 第2个端口值
…
__INPUTS__19   = 最多第20个
```

## 数据出口：把变量交给「组件」/「结束」节点

每个变量在本节点**右侧**都有一个**同名数据出口**（○ 圆圈），执行时输出这个变量**本次刚算出的值**。

### 场景 1：给「组件」节点传参

**前提**：「组件」节点的「输入参数端口数」≥ 1（否则它左侧没有 `in_0` 端口可连）。
调用方蓝图里：

```
SetVariable：  a = 123
               b = hello

连线：SetVariable.a  →  组件.in_0
      SetVariable.b  →  组件.in_1
```

值会经 `__arg_0 / __arg_1` 进入被调用的组件蓝图，由它内部的 `Start` 节点以 `param_0 / param_1`（数据**输出**端口）提供给子图里的连线取用。
⚠ 写变量的时候端口才会出现；如果连不上线，先检查「组件」节点的端口数是不是 0。

### 场景 2：作为组件蓝图的返回值

**前提**：组件蓝图里「结束」节点的「返回值端口数」≥ 1（否则没有 `ret_0` 端口）。
在被调用的**组件蓝图**里：

```
SetVariable：  result = {= {hp} + {bonus}}

连线：SetVariable.result  →  结束.ret_0
```

跑到「结束」节点时，`ret_0` 的值被写进 `__ret_0`，调用方「组件」节点的 `out_0` 端口就能取回它。

### ⚠ 执行顺序决定数据取不取得到

数据出口取的是「上游节点**已经执行过**的输出」。所以 **SetVariable 必须排在组件 / 结束节点的前面**（执行流顺序）；反过来的话下游读到的是空值 `None`，而且不会报错。

## 典型用法

### 1. 蓝图开头定义一堆常量
```
SetVariable batch_text：
  wait_short = 0.5
  wait_long  = 3.0
  game_title = 原神
  threshold  = 0.92
```
→ 下游所有 Wait 节点秒数参数写 `{wait_short}`，Threshold 写 `{threshold}`，一处改处处生效。

### 2. Command 输出存变量
```
连线：
  Command.stdout (绿色) → SetVariable.in_0

SetVariable：
  num_data_inputs = 1
  batch_text：
    cmd_out = {__INPUTS__0}
```
→ 下游 VarSwitch 就能写 `{cmd_out} == "ok"` 做判断了。

## 常见问题

**Q：变量保存后可以改吗？**
→ 可以。后执行的 SetVariable 如果用了同一个变量名，新值会覆盖旧值。

**Q：其他节点可以读取变量吗？**
→ 所有节点的所有文本类参数都支持 `{变量名}` 插值。

**Q：变量类型自动推断吗？**
→ 目前做基础推断：`123`→int、`3.14`→float、`true/false`→bool，其他是字符串。需要精确类型时用 `{= int(xxx)}` 手动转。

**Q：为什么我写了 3 个变量，画布上却没有对应的数据出口？**
→ 出口只按 `batch_text` 里**能解析成功**的行长出来，改完文本约半秒刷新。按这个顺序查：

1. **变量名对不对**：必须字母/下划线/**汉字**开头，不能横杠、数字开头、带空格（见上面「⑤ 变量名写法」）。
2. **那一行有没有半角 `=`**：`a : 1`、`a 1`、整行文字、全角 `a ＝ 1` 都不算。
3. **是不是被当成了注释**：整行以 `#` 或 `//` 开头会被忽略（不会算变量）。
4. **有没有超上限**：最多 20 个出口。
5. **是不是叫 `out_exec`**：与执行出口重名，不生成数据出口。

去哪儿看原因：画布上写错的那行会带 `⚠`、并多出一行 `⚠ N 行不出出参（点「检查格式」）`；
属性面板上方「✓ 检查格式」会列出具体第几行错在哪；点运行前的静态校验、运行日志也会各 WARN 一次。

**Q：数据出口上的连线为什么会自己断掉？**
→ 只有当某次改动让那个**变量名消失**时（改名 / 删掉那行），挂在它上面的线才会断——因为出口本身已经不在了。**改值、调整行顺序都不会断线。**

**Q：这个出口输出的是「变量当前值」还是「刚设置的值」？**
→ 本次刚设置的那个值。如果节点里某一行解析失败（那行不会出现在变量里），对应的出口也就没有值，下游会拿到 `None`。
