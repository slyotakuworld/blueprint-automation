# 🔁 Loop · 循环

> 循环跑圈儿~双击节点进入「循环体子画布」，把要重复的内容装进去，跑满次数或用「跳出循环」结束。
> **循环体不需要接「结束」节点** —— 每轮从「开始」往下跑到最后一个节点，这一轮就算跑完（末尾没接东西也是正常收尾）。
> 「跳出循环」默认走「退出」，把它的「标记为失败」勾上则走「失败」。

---

## 节点外观

- **分类**：🧠 逻辑
- **配色**：紫 (#8250DF / #A371F7)
- **短名**：`loop`

---

## 端口

| 侧 | 类型 | 名称 | 标签 | 说明 |
|----|------|------|------|------|
| 输入 | ▶ 执行 | `in_exec` | ▶ | 进入循环 |
| 输出 | ▶ 执行 | `out_exit` | 退出 | 跑满次数 / 循环体内「跳出循环」（未勾「标记为失败」）后触发，且**所有轮次都正常跑完了** |
| 输出 | ▶ 执行 | `err` | 失败 | 所有轮次里**有任何一轮中途出错**（节点执行异常 / 死循环），或「跳出循环」勾了「标记为失败」时走这里 |

> 💡 循环内容装在「循环体子画布」里（**双击 Loop 节点进入**），不靠端口拉线。
> 早期版本用 `loop_body` 端口「拉出去、末尾再连回 `in_exec`」来回环，**该端口已经移除**，
> 那套兼容代码也一并删掉了；现在的循环一律用子画布。

> ⚠ **「退出」和「失败」只会走一个**，在循环结束（跑满次数或「跳出循环」）之后统一判定：
> 每一轮都看「有没有正常跑完」，只要有一轮中途出错、或者「跳出循环」勾了「标记为失败」→ 走「失败」。
>
> 💡 循环体**不需要接「结束」节点**：从「开始」往下跑到最后一个节点就是这一轮的终点。
> 末尾节点的执行出口悬空（没往下接东西）也算正常收尾，不会判失败。

> ⚠ Loop **没有数据输出端口**，不会输出当前轮次，也不会自动写全局变量。想在循环里计数，得自己备一个计数器（变量全图共享，主图和循环体子画布读写的是同一份）：
>
> 1. **先初始化**：在主图 Loop **之前**放一个 SetVariable，写 `count = 0`。
> 2. **每圈累加**：在循环体子画布内放一个 SetVariable，写 `count = {= {count} + 1}`。
> 3. 循环结束后，`{count}` 就是总圈数。
>
> 🚫 别忘了第 1 步。变量没初始化时 `{count}` 取不到值，`{= {count} + 1}` 会算出 `<eval_error: NameError ...>` 这样的垃圾串，还会被当成字符串写回 `count`，越滚越错——而且**不会报错终止蓝图**，很容易被忽略。

## 循环体子画布

双击 Loop 节点 → 进入一个独立的子画布，里面放「每圈要重复的节点」。

循环体子画布里有三个专用节点（进入子画布后，左侧节点库会多出它们）：

| 专用节点 | 作用 |
|----------|------|
| **再次循环** (Continue) | 跑到这里立即结束本轮、开始下一圈，不执行后面的节点（**不算失败**） |
| **跳出循环** (Break) | 跑到这里立即结束整个循环，跳到 Loop 的出口（**不算失败**）；参数 `as_failure`（标记为失败）勾上则改走「失败」出口 |
| （普通节点） | 一路走到底 → 跑到最后一个节点，本轮就算结束，进入下一圈 |

> 💡 **循环体末尾不需要接「结束」节点**（接了也不会出错，只是没必要）。
> 判定「这一轮跑完了没有」看的是**执行流有没有正常跑到末尾**：
> 跑到了 → 这一轮算成功；中途某个节点执行报错 → 记一次失败。
> 新建的循环体只自动放好一个 `开始` 节点，往下接你的循环动作就行。
> 出错的那些轮**不会中断循环**，下一圈照样跑（详见下方 FAQ）。
>
> 💡 「跳出循环」上还有一个开关：**`as_failure`（标记为失败）**。不勾（默认）→ 走「退出」；
> 勾上 → 整个 Loop 走「失败」出口。用在"循环里发现了不该出现的情况，必须让主流程走失败分支"的场景。

点左上角「← 返回父图」退出子画布。

> 💡 **双击进去只是「看」，不算修改**：只有你在子画布里面真的动了东西（加/删节点、改参数、连线），
> 退出或保存时才会写回 Loop 节点。反复进出、只看不改，蓝图不会变成「有未保存修改」。

## 参数一览

| 参数名 | 编辑器 | 默认值 | 必填 | 说明 |
|--------|--------|--------|------|------|
| `infinite` | ✅ 复选 | `false` | - | 无限循环：勾选后忽略最大迭代，仅手动停止 / 跳出循环才能结束 |
| `max_iterations` | 整数 | `5` | ✅ | 最大迭代次数（1 ~ 10,000,000）；硬防死循环，无限循环模式下不生效 |
| `interval_sec` | 小数 | `1.0` | - | 每轮循环体跑完后的等待秒数（0.0 ~ 60.0） |

## 典型用法

### 1. 每 1 秒按一次 F5，按 100 次（子画布模式）

```
Loop 节点：
  infinite = ❌
  max_iterations = 100
  interval_sec = 1.0

双击 Loop 进入循环体子画布，放：
  Start → PressKey(按 F5 1次)      ← 跑到这里本轮就结束了，不用接「结束」

主图连线：
  Start → Loop.in_exec
  Loop.out_exit → [End]
```

### 2. 无限找图点击，找到「停止」就退出（子画布模式）

```
Loop：infinite = ✅

循环体子画布：
  Start → FindImage(找"停止"按钮)
          ├─ 命中   → Break(跳出循环)
          └─ 未命中 → Mouse(点击"继续")      ← 跑到这里本轮就结束了

主图：
  Start → Loop → Loop.out_exit → ...
```

### 3. 带间隔的批量操作（每 30 秒看一次签到按钮）

```
Loop: max_iterations = 2880, interval_sec = 30
循环体子画布里放「签到」的判断 + 点击逻辑
```

## 常见问题

**Q：怎么退出循环？**
→ 三种方式：① 循环体里放「跳出循环 (Break)」节点；② 跑满 `max_iterations`；③ 蓝图工具栏 ⏹ 停止按钮。
想让「跳出循环」同时把整个 Loop 判成失败，把它的「标记为失败」勾上。

**Q：以前那种「从循环体端口拉线出去、末尾连回 in_exec」的写法呢？**
→ 已废弃。`loop_body` 端口已移除，拉线回环的兼容代码也删了。现在的循环一律用子画布（双击节点进入）。

**Q：循环体里某个节点出错了，会怎样？**
→ 那一圈的执行流会中断，**算一次失败，但 Loop 不会停下来** —— 仍然继续跑下一圈。
全部轮次跑完后统一判定：只要有过失败就走「失败」出口，否则走「退出」。
这样「允许失败几次再成功」的轮询场景不会被一次失败打断。

**Q：「退出」和「失败」分别什么时候触发？**
→ 都在循环结束（跑满 `max_iterations` 或循环体内「跳出循环」）之后判定，且**只走一个**：
所有轮次都正常跑完 → 「退出」；有任何一轮中途出错、或者「跳出循环」勾了「标记为失败」→ 「失败」
（运行日志里会列出是第几轮、断在哪个节点）。

**Q：循环体末尾要不要接「结束」节点？**
→ **不用**。循环体从「开始」往下跑到最后一个节点，这一轮就算跑完；末尾节点的执行出口悬空
也是正常收尾，不会判失败。接一个「结束」也不会出错，只是没必要。

**Q：循环体里走了「没有找到」这类分支，会算失败吗？**
→ 不会。判定只看**这一轮有没有正常跑到末尾**，不看中途经过了哪些端口，也不要求末尾接「结束」。
找图没命中走 `not_found` 是正常节奏，只要那一路跑完，这一轮就算跑完。只有节点**执行报错**才记失败。

**Q：那「顺序执行」「并行执行」的判定口径和循环一样吗？**
→ **一样**。三个容器都不要求接「结束」节点，判定口径统一是
「**只有节点执行异常 / 死循环才算失败**」——跑到最后一个节点、或者末尾出口悬空，都算正常收尾。
（曾经短暂要求过「必须走到结束节点」，已按用户意见还原。）
