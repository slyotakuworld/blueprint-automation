# 🔍 FindImage · 找图

> 给咱一张参考图就在屏幕上找~在超时时间里反复试，找不到还能滚动鼠标页面后继续找。找到了可以顺手点一下再从「成功找到」往下走；一直没找到就走「没有找到」；「执行」出口则是找没找到都能继续。

## 端口

### 输入
| 名称 | 类型 | 标签 | 说明 |
|------|------|------|------|
| `in_exec` | ▶ 执行 | ▶ | 上游触发 |

### 输出
| 名称 | 类型 | 标签 | 说明 |
|------|------|------|------|
| `out_exec` | ▶ 执行 | 执行 | **找没找到都触发**（窗口未定位的异常除外），用来接「无论如何都要继续」的公共后续 |
| `err` | ▶ 执行 | 失败 | **仅**「范围=目标窗口」但目标窗口没定位到时走这里，不会退化成全屏去找 |
| `found` | ▶ 执行 | 成功找到 | 超时内找到了 → 走这条分支 |
| `not_found` | ▶ 执行 | 没有找到 | 跑满超时仍未找到（含模板路径无效）→ 走这条分支 |
| `out_pos` | ○ 数据 (tuple2) | 位置 | 找到时 = 模板中心 + offset 的最终坐标 (X,Y)；没找到 = `None` |

> 💡 **三角（▶）和圆圈（○）的区别**：▶ 是**流程出口**，决定「下一步走哪个节点」；○ 是**数据出口**，只把值传给别的节点的输入端口，自身不驱动流程。所以「成功/没有找到/失败」是三种流程结果，用 ▶；「位置」是个坐标值，用 ○。

> 📌 **`out_exec` 与 `found` / `not_found` 会同时触发**：找到时 `out_exec` + `found` 一起走，没找到时 `out_exec` + `not_found` 一起走。
> 所以**别把 `out_exec` 和这两条分支接到同一段后续**，否则会跑两遍；只想分支就用 `found`/`not_found`，只想无脑往下就用 `out_exec`。

> ⚠ **`err` 和「没有找到」是两回事**：
> - 模板图在超时内没找到 → 走 `out_exec` + `not_found`（这是**正常的业务结果**）；
> - 范围选了「目标窗口」却压根没定位到窗口 → 只走 `err`（参数配错 / 窗口还没开），属于**异常**，**不会静默退化成全屏去找**，也不会走 `out_exec`。

## 参数一览

| 参数 | 编辑器 | 默认值 | 说明 |
|------|--------|--------|------|
| `range_mode` | 下拉 | `window` | 找图范围：`window` 目标窗口（推荐）/ `fullscreen` 全屏 |
| `target_title` | 文本 | `""` | 仅「目标窗口」范围生效：窗口标题子串（支持 `{变量}`）；点「🎯 拾取目标窗口」可自动填 |
| `target_exe` | 文本 | `""` | 仅「目标窗口」范围生效：程序名子串（如 notepad.exe） |
| `target_class` | 文本 | `""` | 仅「目标窗口」范围生效：窗口类名精确匹配 |
| `match_strategy` | 下拉 | `hybrid` | 匹配算法：智能混合 / 模板匹配 / 灰度匹配（详见下一节） |
| `threshold` | 小数 | `0.9` | 匹配阈值（0.3 ~ 1.0），越高越严格，**全代码层统一默认 0.9** |
| `timeout_seconds` | 小数 | `10.0` | 超时秒数（0.5 ~ 600），在超时内反复重试 |
| `template` | 📁 路径 | `""` | 模板图片路径；右侧面板点「📸 截取目标」或「📂 导入图片」可快速填写 |
| `template_b64` | 文本 | `""` | 预览图 base64（只读，不用手填） |
| `scroll_dy` | 整数 | `0` | 滚动重试量，单位是**滚轮刻度数**（1 刻度≈滚轮拨一格）：0=不滚动；负=向下翻页；正=向上翻页。**推荐 1~10**，列表类界面 3~5 通常就够翻一屏。非0时，每轮找图失败后会滚动一次再重试，直到超时。 |
| `after_action` | 下拉 | `none` | 找到后执行：none 仅输出位置 / click 左键单击【推荐】/ double_click 双击 / right_click 右键 |
| `offset` | tuple2 | `(0,0)` | 点击偏移 (X,Y)。Y正=向下，Y负=向上。out_pos 输出的是偏移后的最终坐标 |
| `post_delay_min_ms` / `post_delay_max_ms` | 整数 | `30` / `80` | 「找到后执行」动作做完后、继续下一节点前的等待区间 (ms)，用来等菜单弹出/场景加载 |
| `use_feature_assist` | 下拉 | `off` | 特征识别辅助：off 关闭 / verify 验证模式 / fallback 兜底模式 |
| `features_json` | 多行 | `"[]"` | 特征数据 JSON 数组（通过面板「✂ 从模板截取特征」自动生成） |
| `feature_tolerance` | 整数 | `15` | 位置容差（像素，1~200）。**两种模式含义不同**，见下方「两个特征参数到底怎么用」 |
| `feature_min_hits` | 整数 | `2` | 最少命中特征数（0~20）。命中并通过位置验证的特征数 **≥ 此值** 才算成功；0 = 不要求任何特征命中 |
| `feature_capture_width` | 整数 | `0` | 自动记录不用手填 |
| `feature_template_w` | 整数 | `0` | 自动记录不用手填 |
| `feature_template_h` | 整数 | `0` | 自动记录不用手填 |

> 💡 **目标窗口与「📸 截取目标」联动（仅制作模板时的便利）**：若已配置并拾取到目标窗口，
> 点「📸 截取目标」时框选范围会自动限定在该窗口内（窗口外点不进去、拖到边界自动贴边），
> 保证截出的模板确实取自这个窗口。若配置了但当前找不到该窗口，框选工具会回退成全屏框选并打出日志提示——
> 这**只是画框工具的制作便利**，与运行时无关：**运行时**范围选「目标窗口」却找不到窗口，是直接走 `err`，绝不回退全屏。

## 三种匹配算法

| 算法 | 中文 | 适用场景 | 抗变化能力 | 速度 |
|------|------|----------|-----------|------|
| **hybrid** | 智能混合【推荐】 | 大多数场景，兜底能力强 | 高 | 中 |
| template | 模板匹配(彩色BGR) | 尺寸固定、画面清晰、颜色稳定的 UI 按钮/图标 | 低（颜色/缩放/旋转一变就找不到） | 最快 |
| gray | 灰度匹配 | 颜色会变但形状不变的按钮（选中/未选中态） | 中（容忍颜色变化） | 快 |

> 三种算法都自带**多尺度搜索**（实测范围约 0.45~1.8，其中 0.8~1.2 为核心区间），可覆盖一定程度的缩放；
> 但都**不抗旋转与局部遮挡**。这类场景建议改用其它手段（例如先缩小范围、或用文字识别定位锚点）。

### hybrid 智能混合的两级级联
1️⃣ 先跑彩色多尺度模板匹配
2️⃣ 没找到 → 再跑灰度多尺度模板匹配（吃下颜色变化）

→ 两级中**任意一层命中**就算找到，并在日志里标明是哪一层命中的（方便调阈值）。

## ✨ 测试匹配按钮（必看！）

右侧属性面板有个 **「测试匹配」** 按钮，调阈值必备神器：

### 特点
1. 点按钮会弹**模态进度条**，防止你在匹配过程中乱点
2. 进度条每处理 3 个尺度就刷新 UI（不会界面卡死）
3. **按节点当前的「找图范围」截屏幕**：目标窗口范围内 or 全屏，和实际运行时用的截图口径完全一致
4. 严格按节点当前的匹配算法设置跑（hybrid 就两级、template 就只一层彩色，和运行时 100% 一样）
5. **特征识别辅助也一起跑，而且用的是运行时同一个函数**（不是另写一套）：
   - **验证模式**：彩色/灰度命中后，再逐个校验特征是否还在原位；校验不过 → 结果直接显示 ❌ 未找到
   - **兜底模式**：彩色/灰度没命中时，才用特征全屏搜并反推模板中心；命中就显示 ✅ 找到 + 特征反推的中心坐标
   - 特征列表为空、或「最少命中特征数」调得比可用特征还多，测试结果会**如实报 ❌** 并附原因（和运行时口径一致，不会静默放行）
6. 结果弹窗里会告诉你：**命中了哪一层算法 / 得分 / 坐标 / 级联路径**（例如：`彩色→灰度`，表示彩色层没找到、最后用灰度找到的）；
   开启了特征辅助时还会多出「特征数据 N 个 / 特征校验 ✅❌」和一段**特征辅助日志**（容差、命中数、scale 校准对上几对、模板原点等，和运行时日志同源）
7. 有**防重入标志**，连点不会并发执行
8. 任意提前退出分支都会清理临时文件、恢复窗口

> 坐标口径提醒：**验证模式不改坐标**（坐标仍旧来自彩色/灰度命中位置，特征只当"放行/拦下"的开关）；
> **兜底模式才由特征反推坐标**（此时"命中矩形"显示 `(x, y, 0, 0)`、"中心坐标"就是反推出来的模板中心）。

→ 每张图第一次用，**先点一下测试匹配**再决定阈值设多少，不用每次都跑完整蓝图！

## 找图范围 range_mode

### window 目标窗口（推荐）
- 只在「目标窗口」定位到的那个窗口范围内找图（避免跨窗口误匹配长得像的按钮）
- 输出坐标是**相对窗口左上角**的坐标，配合 Mouse「目标窗口」模式无缝点击
- 窗口从哪来：本节点自己的「目标窗口」定位参数（`target_title` / `target_exe` / `target_class`，**至少填一个**）
- 填定位条件有两种方式（都是制作期的便利工具，跟运行时无关）：
  - 🎯 **拾取目标窗口**：鼠标点哪个窗口就用哪个。**最小化的窗口点不到，所以不会被拾取。**
  - 📋 **从列表选择**：列出所有窗口双击选择。**最小化的窗口也会列出**（排在最后，状态列标「最小化」），
    适合「目标窗口现在最小化着，先把定位条件填好，回头再让它跑」。
    窗口最小化不影响运行时定位——定位靠标题/程序名/类名，不靠窗口是否显示在屏幕上。
- ⚠ 定位不到窗口 → 直接走 `err` 失败出口，**不会退化成全屏去找**

### fullscreen 全屏
- 在整块屏幕上找图
- 输出**绝对屏幕坐标**，Mouse 节点也要切到「全屏」模式

> 📌 两个模式输出坐标的口径不同：`window` 给相对坐标、`fullscreen` 给绝对坐标。下游 Mouse 节点的「坐标基准」要和这里配对，否则会点偏。

## 特征识别辅助 use_feature_assist

在模板匹配之外，再用一张或多张小特征图做交叉验证：

| 模式 | 作用 |
|------|------|
| **off** | 不用特征辅助 |
| **verify 验证模式** | 模板匹配成功 → 再跑一遍特征辅助验证；特征也通过才算成功；更严格，减少误判 |
| **fallback 兜底模式** | 模板匹配失败 → 用特征辅助再试一次；找到了也算成功；更宽松 |

> 💡 这里的「兜底」是**匹配算法层**的补充手段（多一种找法），和「范围找不到就降级成全屏」完全不同——那是被明令禁止的静默降级，不会发生。

→ 特征辅助内部**跟随主算法，且层数与主匹配保持一致**：主算法选「灰度匹配」→用灰度匹配；选「智能混合」→用「彩色→灰度」两级；选「模板匹配」→用彩色匹配。

→ 特征怎么加？右侧面板点 **「✂ 从模板截取特征」**，在预览图上框选小区域（比如按钮里的一个字母、一个小图标），至少框 2 个不同位置做交叉验证。
→ 模板图太大/太小看不清时，弹窗里有 **「➕ 放大 / ➖ 缩小 / 🖥 适应窗口 / 1:1 原始像素」** 四个按钮，
   也可以 **按住 Ctrl 滚滚轮** 缩放（不按 Ctrl 时滚轮用于上下滚动查看）；打开时会自动「适应窗口」，先让你看到整张模板。
→ 换模板后旧特征会失效，程序**自动清空**特征数据并打日志提示重新截取（Ctrl+Z 撤销换模板时会一起还原）。

### 通过 / 失败怎么判（一句话）

**命中并通过位置验证的特征数量 ≥「最少命中特征数」→ 成功；小于它 → 失败。** 验证模式、兜底模式都按这个口径。
特别的：**没有任何可用特征图时，命中数按 0 算**——所以只有把「最少命中特征数」设为 `0` 才会放行，否则直接判失败（运行时打 WARN，属性面板也会红字提醒），**不会静默跳过验证**。

### 两个特征参数到底怎么用

| 参数 | 兜底模式（模板没找到，靠特征反推位置） | 验证模式（模板已找到，在命中位置旁边验证特征） |
|------|------------------------------------|------------------------------------------|
| `feature_tolerance` | **参与判定**：以第一个命中特征为基准，推算其他特征应在的位置，实际位置与推算位置的欧氏距离超过它 → 丢弃该特征；丢到不够「最少命中数」就判本次失败 | **不参与判定**：只用来决定搜索窗口开多大（窗口宽 = 特征宽×缩放 + 容差×2，最小 30px）。调大 = 搜索更宽松、更容易通过，但也削弱了「验证」的收紧作用 |
| `feature_min_hits` | 有效命中数 ≥ 此值才算成功 | 验证通过的特征数 ≥ 此值才算成功 |

> 所以「容差」在两种模式下是**两件事**：兜底模式是「允许多大位置偏差」，验证模式是「搜索窗口的宽松度」。调参前先确认当前用的是哪种模式。

## 典型用法

### 1. 最常见：在目标窗口里找到按钮就点一下
```
FindImage：
  template        = 截图按钮模板.png
  match_strategy  = hybrid 【推荐】
  range_mode      = window
  target_exe      = game.exe      ← 目标窗口定位（标题/程序名/类名至少填一个）
  threshold       = 0.9
  timeout_seconds = 10
  after_action    = click 【左键单击】
  offset          = (0, 0)
```
→ 找到 → 走 `found` 分支接后续（比如接鼠标/条件判断）；
→ 超时没找到 → 走 `not_found` 分支做重试或跳过；
→ 连 `err` 出口可以兜「目标窗口没开」这种异常。

### 2. 找不到就滚一下页面再找（长列表场景）
```
FindImage：
  range_mode      = window
  target_class    = Notepad     ← 或者填标题/程序名
  scroll_dy       = -4   ← 负=页面向下翻；单位是滚轮刻度，3~5 一般够翻一屏
  timeout_seconds = 20
  after_action    = click
```
→ 每轮找不到就向下滚 4 格，再重试，直到 20 秒超时。
→ ⚠ 别写成 -400：那是 400 个滚轮刻度，会直接滚到底把目标跳过，看着像「找图失效」。

### 3. 找桌面/任务栏图标（用全屏）
```
FindImage：
  range_mode = fullscreen
  template   = 桌面图标.png
→ 下游 Mouse 的「坐标基准」也要选「全屏」
```

## 常见问题

**Q：明明看到了却找不到？**
→ 第一步先点「测试匹配」：
- 如果显示「彩色匹配得分 0.78 < 阈值 0.9」→ 把阈值调低一点（0.85 左右）
- 如果彩色/灰度都没过 → 重新截一张更清晰的模板，或核对找图范围是否一致
- 另外检查窗口是不是被最小化/挡住了

**Q：误判（不是按钮却当成按钮）怎么办？**
→ 把 threshold 调高到 0.93+，或者开 use_feature_assist = verify 模式加特征交叉验证。

**Q：为什么明明没找到却没走 err，反而走了 not_found？**
→ 这是设计如此。`err` 只负责「范围=目标窗口但窗口没定位到」这种配置/环境错误；**模板在超时内没出现**属于正常业务结果，走 `out_exec` + `not_found`，下游自己决定怎么处理（重试、跳过、换流程）。

**Q：`out_exec` 和 `found` / `not_found` 能随便接吗？**
→ 不能同时接。找到时 `out_exec` 和 `found` 会**一起触发**，没找到时 `out_exec` 和 `not_found` 一起触发；两条都接同一段后续就会跑两遍。要分支就只用 `found`/`not_found`，要无脑继续就只用 `out_exec`。

**Q：范围选了「目标窗口」，但有时会误点到别的窗口怎么办？**
→ 不会。范围选「目标窗口」时，找图**只在那个窗口内**进行，且找不到窗口直接失败——不存在「退回全屏乱找」导致误点的情况。

**Q：滚动方向经常搞反？**
→ 口诀：**负=页面向下翻**（滚到下面更多内容）。跟 pyautogui 的符号约定保持一致：
```
scroll_dy > 0 → 滚轮向前（朝屏幕外面转）→ 页面向上
scroll_dy < 0 → 滚轮向后（朝你手心转）→ 页面向下【想找列表下方东西，用负值！】
```

**Q：滚动量填多少合适？**
→ 单位是**滚轮刻度数**（1 刻度≈滚轮拨一格），**推荐 1~10**，列表类界面 3~5 通常就够翻一屏。
   填过头（比如 -300）会一次滚到底、把目标直接跳过，现象看起来像「找图不工作」，先怀疑这里。

**Q：开了「验证模式」之后找图突然永远找不到了？**
→ 先看属性面板有没有红字提醒、日志里有没有 `没有可用特征图`／`可用特征只有N个 < 最少命中M个`：
- **没有特征**（刚换过模板、或没截取过特征）→ 点「✂ 从模板截取特征」补上；只需临时放宽的话，把「最少命中特征数」设为 `0`；
- **特征数少于「最少命中特征数」** → 这种组合永远不可能通过，把「最少命中特征数」降到不超过特征数（默认 2 个特征配 2）。

**Q：为什么「验证模式」调大「位置容差」反而更容易通过？**
→ 因为验证模式下容差**不判位置对错**，只用来把搜索窗口开大（窗口宽 = 特征宽×缩放 + 容差×2）。想真正收紧验证，应该加特征、或把「最少命中特征数」提高。兜底模式下容差才是「允许多大位置偏差」。

**Q：Y 轴 offset 方向跟 Mouse 一样吗？**
→ 一致：Y 正值 = 向下，Y 负值 = 向上。和 Mouse 节点 offset 参数约定保持一致，不用翻来覆去记。
