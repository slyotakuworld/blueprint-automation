# 🔀 变量与流程控制全解

蓝图像积木，但**变量是蓝图像编程语言一样强大的秘密武器**。这一节把变量、VarSwitch 多条件分支、Loop 循环、Sequence 顺序执行这几个核心控制流拆透。

---

## 一、变量系统总览

### 变量在哪里存在？
每个**蓝图运行时实例**都有一张独立的字典 `_variables`：
```
{
  "hp":        85,          # int
  "mana":      120.5,       # float
  "hp_text":   "HP: 85",    # str
  "name":      "赫萝",      # str
  "ok":        True,        # bool
  "pos":       (100, 200),  # tuple2
}
```
→ 两个蓝图并行跑时，变量**互不影响**。

### 能存什么类型？
| 类型 | 字面量写法 | 说明 |
|------|-----------|------|
| `int`   | `42`, `0`, `-5` | 整数 |
| `float` | `3.14`, `1.0` | 小数 |
| `str`   | `"赫萝"`, `'狼'` | 字符串 |
| `bool`  | `True`, `False` | 布尔 |
| `tuple2`| `(1280, 720)`   | 坐标对（Mouse/FindImage 传位置） |
| `list`, `dict`, `None` | `[1,2,3]`, `{"a":1}`, `None` | 少用，大多走 JSON 串 |

### 字符串插值：{变量名} 魔法
几乎所有节点的文本/多行文本参数都支持 `{变量名}` 语法：
```
PressKey.text = "今天 {name} 想吃 {food}，一共 {count} 个苹果 🍎"

如果变量 name="赫萝", food="面包", count=3 → 实际写入剪贴板的是：
"今天 赫萝 想吃 面包，一共 3 个苹果 🍎"
```

→ **找不到变量会报错终止蓝图**（不会默默用空字符串代替），因为你大概率写错了名字，需要立刻知道。

### 哪些节点会自动存全局变量？

除了 SetVariable 手动设置外，以下节点执行时会自动写入全局变量：

| 节点 | 写入的变量 | 说明 |
|------|-----------|------|
| **Clipboard** | `{output_var_name}`（默认 `clip_text`） | read 模式读到的文本自动存为指定变量名 |
| **HttpRequest** | `web_` + JSON 响应的每个 key | 勾选 save_json_to_vars 时自动拆 JSON |

> 🐺 这两个节点的变量不需要手动 SetVariable，执行完直接 `{clip_text}`、`{web_token}` 就能用啦~

## 二、SetVariable · 设置变量

SetVariable 是存变量的主力节点。在属性面板的 `batch_text` 多行文本框里，每行写 `name = value` 即可：

### ① 字面量赋值
```
hp = 100
count = 0
user = Alice
is_open = true
```

> ⚠ **非常重要**：`name = "苹果"` 里的引号**不会被剥掉**，会作为值的一部分存起来！不想要引号直接写 `name = 苹果`。

### ② 引用其他变量 / 输入端口值
```
# 引用之前设置的变量
final = {hp} + {bonus}

# 引用数据输入端口（num_data_inputs 设了几个就有几个 in_0/in_1…）
cmd_out = {__INPUTS__0}
```

### ③ 表达式计算 `{= 表达式}`
```
# 算术
total = {= {hp} + {bonus}}
double = {= {count} * 2}

# 端口值做计算（Command.stdout 是 str，要先转 int！）
sum = {= int({__INPUTS__0}) + int({__INPUTS__1})}
```

### ④ 注释
```
# 这一行以 # 开头，是注释
// 双斜线也是注释
```

### ⑤ 数据出口：把变量传给「组件」/「结束」节点

`batch_text` 里写了几个变量，节点**右侧就会长出几个同名数据出口**（○），执行时输出刚设置的那个值。

```
SetVariable： a = 123
连线：SetVariable.a  →  组件.in_0
```

被调用的组件蓝图里，这个值从它内部 `Start` 节点的 `param_0`（数据输出端口）取用；
组件要把结果交还给调用方，则反过来连：`SetVariable.xxx → 结束.ret_0`，调用方从 `组件.out_0` 取回。

> ⚠ **SetVariable 必须排在组件 / 结束节点之前执行**（执行流顺序）——数据出口给的是「上游已经执行过的输出」，
> 顺序反了下游只会读到空值 `None`，而且不报错。

> ⚠ **写不对的行不会生成出口**：变量名须以**字母 / 下划线 / 汉字**开头
> （`血量 = 100` ✓、`hp = 100` ✓；`my-var`、`1a`、带空格的 ✗）；整行以 `#` 或 `//` 开头算注释、也不算变量。
> 卡在这个点上时：画布上该行会标 `⚠`、「✓ 检查格式」按钮会指出第几行错、运行日志也会 WARN。

> 详细的 batch_text 语法和端口用法见 [SetVariable 节点详解](node_SetVariable.md)。

## 三、VarSwitch · 多条件分支（if / elif / else）

### 本质就是一串 if elif else
```
condition_list = [
  (mode, left, op, right, label),  ← cond_0
  (mode, left, op, right, label),  ← cond_1
  ...
]

按顺序依次评估：
  if   cond_0 为真 → case_0_exec  ▶
  elif cond_1 为真 → case_1_exec  ▶
  elif cond_2 为真 → case_2_exec  ▶
  ...
  全假            → default_exec  ▶（default 没连下游就静默）
```

### 两种评估模式 mode
| mode | 含义 | 要求 |
|------|------|------|
| **var**（变量比较） | 取 `variables[left]` 做运算 | left 是变量名 |
| **literal**（字面量比较） | 直接把 left 字面量值当左操作数 | left 能解析成 int/float/str/bool/tuple2 |

### 支持的运算符 op（按大类分）
| 类别 | 运算符 | 例 |
|------|--------|-----|
| 比较 | `==`, `!=`, `<`, `<=`, `>`, `>=` | hp `>` 50 |
| 包含 | `in`, `not_in` | "苹果" `in` bag_text |
| 类型 | `is_int`, `is_float`, `is_str`, `is_bool`, `is_none`, `is_tuple2` | money `is_int` |
| 字符串 | `starts_with`, `ends_with`, `contains_ci`（大小写不敏感包含） | title `starts_with` "第" |

### Inspector 里怎么加条件？
右侧属性面板「➕ 添加条件」一行一行加：
1. 每一行 = 一个条件分支
2. 选 mode（var 还是 literal）
3. left、op、right 填好
4. label 可选（会显示在节点图标上，短一点如"血低"）
5. 想删点「🗑」；想调顺序点「上移/下移」

添加了条件后，节点图标会自动长出来对应的 **case_N_exec ▶ 输出端口**。

## 四、Loop · 循环

循环的内容装在**循环体子画布**里（双击节点进入编辑）。**循环体不需要接「结束」节点** —— 每轮从「开始」往下跑到最后一个节点，这一轮就算跑完。

| 参数 | 说明 |
|------|------|
| `infinite` | 勾选 = 无限循环（只能手动停止、或用「跳出循环」结束） |
| `max_iterations` | 最大迭代次数（未勾 `infinite` 时生效） |
| `interval_sec` | 每轮循环体跑完后的等待秒数 |

**出口**（只会走一个）：
- **退出** `out_exit`：跑满次数、或循环体里走了「跳出循环」（未勾「标记为失败」），且所有轮次都正常跑完了
- **失败** `err`：有任何一轮中途出错（节点执行异常 / 死循环），或「跳出循环」勾了「标记为失败」

> ⚠ 循环体**不要求接「结束」**：跑到最后一个节点就算一轮完成，末尾节点的执行出口悬空也是正常收尾。
> 所以 `not_found` / `no` 这类轮询分支不会被误判成失败。
> 这条口径 **顺序体 / 并行体也一样** —— 三个容器统一是「只有异常报错才失败」。

> ⚠ Loop **没有数据输出端口**，不会输出当前轮次，也不会自动写全局变量。
> 想在循环里计数得自己备一个计数器（变量全图共享，主图和循环体读写的是同一份）：
> ① 循环**之前**放 SetVariable 写 `count = 0`；② 循环**体里**放 SetVariable 写 `count = {= {count} + 1}`。

### 无限循环 + 找到了就跳出

```
Loop(infinite)
  循环体子画布：
    IfImageDetect(找到BOSS?)
      yes → 跳出循环(Break)   ← 立即结束整个循环，走「退出」
      no  → Wait(2s)          ← 没找到就等一会，进入下一轮（跑到这里本轮就结束了）

Loop.退出 → 收尾工作
```

> 「再次循环(Continue)」= 立即结束本轮、开始下一轮；「跳出循环(Break)」= 立即结束整个循环。
> 两者都**不算失败**。「跳出循环」还有个「标记为失败」开关，勾上就让 Loop 走「失败」出口。

## 五、Sequence · 顺序执行

顺序执行的内容也装在**子画布**里（双击节点进入编辑），从 `Start` 一条线串行跑到终点，**不做任何条件判断**。

```
in_exec → 顺序体子画布： Start → A → B → C → out_done
```

- 适合：做完 A 再做 B 再做 C，而 A / B / C 各自内部又是一串节点 —— 打包成一个块，主蓝图更清爽。
- ⚠ **不需要接「结束」节点**：跑到最后一个节点就算跑完，走「完成」出口。
  只有子画布里有节点**执行报错**（抛异常、死循环）才走「失败」。
- 想中途提前收工？顺序体里放「**退出串行**」节点 —— 跑到它就立即结束整个顺序执行。
  它默认走「完成」，勾上「标记为失败」则走「失败」。
- 需要分支请用「条件判断(VarSwitch)」；需要重复请用「循环(Loop)」；需要多条同时跑请用「并行执行(Parallel)」。

## 六、典型组合套路 🍎

### 套路 1：血量监视（循环 + 分支）
```
Start → OpenApp → Loop(infinite)
  循环体子画布：
    IfImageDetect（或其他手段获取 hp 变量）
    VarSwitch：
      var hp <  30 → PressKey(按吃药快捷键) → Notify("吃药！血量极低")
      var hp <  60 → Notify("血量有点少，注意")
      default     → （啥也不做）
    Wait(0.5s)  ← 每 0.5 秒检查一次，别跑太满（跑到这里本轮就结束了）
```

### 套路 2：每天签到 5 次（计数循环 + 找图点击）
```
Start → OpenApp →
  Loop(max_iterations=5)
    循环体子画布：
      FindImage("签到按钮", after_action=click)
      Notify("完成第 {count} 次签到")   ← count 是自己用 SetVariable 维护的计数器
      Wait(1s)      ← 跑到这里本轮就结束了，不用接「结束」
  退出 →
      Notify("5 次签到全完成啦~") → End
```

### 套路 3：三个弹窗一起盯（并行执行）
三处弹窗都可能冒头，用「并行执行」同时盯住（分支末尾不用接「结束」）：
```
Parallel
  并行体子画布：
    分支入口#1 → FindImage("签到弹窗", after_action=click)
    分支入口#2 → FindImage("公告弹窗", after_action=click)
    分支入口#3 → FindImage("活动弹窗", after_action=click)

out_done → 三条都跑完，继续跑下游流程
```

想要"哪个先冒头就立刻收工"，在每条分支末尾放一个「**退出并行**」节点——
任一分支走到它就会中止整个并行结构（其它分支跑完手上那个节点就退出）。
它默认整体走 `out_done`，勾上「标记为失败」则整体走 `err`。

> ⚠ 三个找图是**真并发**，但鼠标只有一个 —— 同时点击可能互相打架。
> 如果只想"哪个先冒头就处理哪个"，更稳的是用一个 Loop 轮流找（见套路 1）。
