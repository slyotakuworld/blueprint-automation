# 🔤 OcrRecognize · 文字识别

> 用内置 OCR 引擎识别图像里的文字和数字~可以自己截 ROI，也能直接吃上游截图节点给的图像，识别结果存成变量、还能按整行/逐条输出。

---

## 节点外观

- **分类**：👁 视觉感知
- **配色**：深蓝 (#0b3d61 / #29b6f6)
- **短名**：`ocr_recognize`

---

## 端口

### 输入
| 名称 | 类型 | 标签 | 说明 |
|------|------|------|------|
| `in_exec` | ▶ 执行 | ▶ | 上游触发 |
| `in_image` | ○ 数据 | 图像(BGR) | 「图片来源=用输入图像」时，接上游截图节点的 image_bgr |

### 输出
| 名称 | 类型 | 标签 | 说明 |
|------|------|------|------|
| `out_done` | ▶ 执行 | 完成 | 识别到至少一条文字 |
| `err` | ▶ 执行 | 失败/无文字 | 引擎不可用 / 图像为空 / 没识别出文字 |
| `text` | ○ 数据 | 整屏文本 | 所有识别结果，多行用换行连接 |
| `items` | ○ 数据 | 识别条目(列表) | 每条含 `text` / `conf`(置信度) / `box`(坐标) / `index` |
| `first_text` | ○ 数据 | 第一条文字 | 识别到的第一条（常用来存单个数字/词） |
| `count` | ○ 数据 | 识别条数 | 识别出的条数 |

---

## 参数一览

| 参数名 | 编辑器 | 默认值 | 说明 |
|--------|--------|--------|------|
| `source_mode` | 下拉 | `roi` | 图片来源：`roi`=自己截 ROI / `input_image`=用输入图像 |
| `temp_target_title` | 文本 | `""` | 窗口标题子串（仅 roi 模式）；支持 `{var}` |
| `temp_target_exe` | 文本 | `""` | 程序名子串（仅 roi 模式）；支持 `{var}` |
| `temp_target_class` | 文本 | `""` | 窗口类名精确匹配（仅 roi 模式）；支持 `{var}` |
| `roi` | 四元组 | `(0,0,0,0)` | 识别区域 (x, y, w, h)；全 0 = 整个范围。可点工具栏「🖱 框选ROI」鼠标框选 |
| `lang` | 下拉 | `ch` | `ch`=中文(含数字) / `en`=英文(含数字，更快) |
| `save_to_var` | 文本 | `ocr_text` | 整屏文本写入这个变量名；留空=不写 |
| `first_to_var` | 文本 | `""` | 第一条文字写入这个变量名；留空=不写 |

> 💡 **工具栏快捷操作**（选中文字识别节点时出现在属性面板上方）：
> - 🖱 **框选ROI**：鼠标拖框选识别区域，自动回填 `roi` 并显示预览图。
> - 🎯 **拾取临时窗口** / 📋 **从列表选择**（仅「自己截 ROI」模式）：点窗口或从列表选，自动回填 `temp_target_*`。
> - 🔍 **测试识别**：按当前临时目标+ROI 现场截一张图跑一次 OCR，弹窗显示识别结果（不用运行整张蓝图，方便调 ROI 和语言）。

## 典型用法

### 1. 识别血量/金币数字
```
OcrRecognize(图片来源=自己截ROI, 临时目标·程序名=game.exe, ROI=(血量区域), lang=en, first_to_var=hp)
   └─ 识别后 {hp} 就是血量数字，VarSwitch 写 {hp} < 30 就能判断是否吃药
```
识别**数字**用 `lang=en` 更快更准；识别**中文**用 `lang=ch`。

### 2. 配合截图节点
```
Screenshot(ROI=数字区) ── image_bgr ──→ OcrRecognize(图片来源=用输入图像, first_to_var=num)
```
先截好图再识别，逻辑更清晰、也方便同一张图反复识别。

### 3. 识别整屏文字做状态判断
```
OcrRecognize(save_to_var=screen_text)
   └─ VarSwitch({screen_text} 包含 "开始游戏") → 满足 → Mouse 点击
```

## 依赖与打包（重要）

OCR 引擎是**内置本地引擎**（PaddleOCR），但**不烧进 EXE**，而是放在 exe 同级的 `ocr_runtime/` 目录按需加载：

- **编辑器内运行**：直接可用（项目 venv 里已装 paddle）。
- **导出独立 EXE**：若蓝图用了本节点，导出对话框会提示，把 `ocr_runtime/` 目录放到 EXE 同级即可；**没用 OCR 的蓝图导出完全不带 OCR，体积不涨**。

## 常见问题

**Q：为什么第一次识别很慢？**
→ 引擎第一次调用要加载模型（几秒），之后常驻复用，逐条识别只要几十~几百毫秒。

**Q：识别失败走 err 了？**
→ 可能原因：没装 paddle（报「OCR 未安装」）、图像为空、或真的没识别出文字。看日志里的 `[OCR]` 提示。

**Q：怎么识别得更准？**
→ ROI 框得越小越准；纯数字用 `en`；截图要清晰、对比度高，别截到半透明/毛玻璃背景。
