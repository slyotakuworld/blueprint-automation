# 🔤 OcrRecognize · 文字

> 用内置 OCR 引擎识别屏幕上的文字和数字~按「识别范围」现场截图（目标窗口 / 全屏）后识别，
> 输出**整屏文本**和**逐条识别结果**；还能填一段文本或正则表达式去匹配整屏文本，
> 命中走「匹配到」、没命中走「未匹配到」；一条文字都没识别到就走「无文字」（与「失败」分开，属于正常业务结果，同时也会触发「完成」）。

## 节点外观

- **分类**：👁 感知
- **配色**：深蓝 (#0b3d61 / #29b6f6)
- **短名**：`ocr_recognize`

## 端口

### 输入
| 名称 | 类型 | 标签 | 说明 |
|------|------|------|------|
| `in_exec` | ▶ 执行 | ▶ | 上游触发 |

> 📌 本节点**没有图像入参**：要识别哪块画面，由节点自己的「识别范围 + ROI」决定，不需要上游喂图。

### 输出
| 名称 | 类型 | 标签 | 说明 |
|------|------|------|------|
| `out_done` | ▶ 执行 | 完成 | 识别流程正常跑完（识别到文字时触发）；数据端口此时已就绪 |
| `no_text` | ▶ 执行 | 无文字 | 跑完了但一条文字都没识别到（与「失败」分开，是**正常业务结果**） |
| `matched` | ▶ 执行 | 匹配到 | 填了「匹配文本」且整屏文本命中 |
| `not_matched` | ▶ 执行 | 未匹配到 | 填了「匹配文本」但整屏文本没命中 |
| `err` | ▶ 执行 | 失败 | 截图失败 / 目标窗口没定位到 / 引擎异常 / **匹配表达式非法**（不会触发「完成」） |
| `text` | ○ 数据 | 整屏文本 | 所有识别结果，多行用换行连接 |
| `items` | ○ 数据 | 识别条目(列表) | 每条含 `text` / `conf`(置信度) / `box`(坐标 x,y,w,h) / `index` |

#### 出口触发规则（照着连就不会连错）

| 情况 | 会触发哪些出口 |
|------|----------------|
| 识别到文字，**没填**「匹配文本」 | `完成` |
| 识别到文字，**填了**「匹配文本」，命中 | `完成` + `匹配到` |
| 识别到文字，**填了**「匹配文本」，没命中 | `完成` + `未匹配到` |
| 识别到 0 条文字 | `完成` + `无文字`（不再做匹配判定） |
| 截图/引擎/窗口/正则出错 | 只 `失败`（不触发「完成」） |

> ⚠ **`完成` 会和 `匹配到` / `未匹配到` / `无文字` 同时触发**（和找图节点的「执行」出口一个道理）。
> 所以别把 `完成` 和这些分支接到同一段后续，否则会跑两遍：
> 想分支就只用 `匹配到` / `未匹配到`；想「无论如何都继续」就只用 `完成`。

> 💡 **为什么不做「第一条文字」和「识别条数」出口？**
> 只输出第一条没有意义，条数也能从 `items` 列表看出来。需要复杂判断时，
> 要么用下面的**文本匹配**在节点内解决，要么把 `text` / `items` 交给外部工具处理。

## 参数一览

| 参数名 | 编辑器 | 默认值 | 说明 |
|--------|--------|--------|------|
| `range_mode` | 下拉 | `window` | 识别范围：`window` 目标窗口 / `fullscreen` 全屏 |
| `target_title` | 文本 | `""` | 仅「识别范围=目标窗口」时生效：窗口标题子串，支持 `{变量}`；点「🎯 拾取目标窗口」可自动填 |
| `target_exe` | 文本 | `""` | 仅「识别范围=目标窗口」时生效：程序名子串（如 notepad.exe），支持 `{变量}` |
| `target_class` | 文本 | `""` | 仅「识别范围=目标窗口」时生效：窗口类名精确匹配，支持 `{变量}` |
| `roi` | 四元组 | `(0,0,0,0)` | 识别区域 (x, y, w, h)；全 0 = 整个范围。可点工具栏「🖱 框选ROI」鼠标框选 |
| `roi_preview_b64` | 文本 | `""` | ROI 缩略图（自动记录不用手填） |
| `lang` | 下拉 | `ch` | `ch`=中文(含数字) / `en`=英文(含数字，更快) |
| `match_mode` | 下拉 | `contains` | 匹配方式：`contains` 包含文本 / `regex` 正则表达式 |
| `match_text` | 文本 | `""` | 要匹配的内容；**留空 = 不做匹配** |

> 📌 **参数按识别范围自动显隐**：识别范围=**全屏**时，目标窗口定位参数不显示（用不上）；
> 识别范围=**目标窗口**时才显示 `target_title` / `target_exe` / `target_class`。

> 💡 **工具栏快捷操作**（选中文字节点时出现在属性面板上方）：
> - 🖱 **框选ROI**：鼠标拖框选识别区域，自动回填 `roi` 并显示预览图。
> - 🎯 **拾取目标窗口** / 📋 **从列表选择**（仅「识别范围=目标窗口」）：点窗口或从列表选，自动回填 `target_title/exe/class`。
>   **从列表选择会把最小化的窗口也列出来**（排在最后、状态列标「最小化」）；拾取要靠鼠标点，最小化的窗口点不到所以不列。
> - 🔍 **测试识别**：按当前「识别范围 + 目标窗口 + ROI」现场截一张图跑一次 OCR，弹窗显示标注图、文字列表，**以及匹配结果**（填了匹配文本时）。**若识别范围=目标窗口但找不到窗口，会直接提示并中止，不会退化成全屏截图。**

## 识别范围 range_mode

和「找图」节点的「找图范围」一个道理：

### window 目标窗口（推荐）
- 只在「目标窗口」定位到的那个窗口内截图识别，`roi` 坐标**相对窗口左上角**
- 窗口从哪来：本节点的「目标窗口」定位参数（`target_title` / `target_exe` / `target_class`，**至少填一个**）
- ⚠ 定位不到窗口 → 直接走 `err` 失败出口，**不会退化成截全屏识别**

### fullscreen 全屏
- 在整块屏幕上截图识别，`roi` 坐标相对**屏幕左上角**

## 文本匹配（match_mode / match_text）

识别完文字后，可以顺手在**整屏文本**里找一段内容，命中与否直接变成两条流程分支，
省掉「写变量 + 条件判断」的来回折腾。

| 匹配方式 | 行为 |
|----------|------|
| `contains` 包含文本 | 整屏文本里**出现这几个字**就算命中。**区分大小写**（`Test` 匹配不到 `test`） |
| `regex` 正则表达式 | 把「匹配文本」当成正则去 `search` 整屏文本，例如 `[Hh]ello`、`金币\s*(\d+)`、`error\|失败` |

要点：
- **留空 = 不做匹配**：识别到文字时只走「完成」出口，`匹配到` / `未匹配到` 都不会触发。
- 一旦填了，两条分支必走其一：命中 `匹配到`，没命中 `未匹配到`。
- **`无文字` 时不评估匹配**：一条文字都没识别到，就走「完成 + 无文字」，需要把「没文字」当「没匹配到」处理的话，两条都接上即可。
- **正则写错**（例如少个括号）→ 直接走 `err`，日志里有 `匹配表达式非法` 提示；此时 `text` / `items` 照样带出来，方便排查。
- 「匹配文本」**不做 `{变量}` 插值**——正则里的 `{}` 量词（如 `\d{3}`）会和插值语法打架，所以这里一律按字面量处理。

## 典型用法

### 1. 判断界面上有没有出现某段提示（不用变量）
```
OcrRecognize(识别范围=目标窗口, 目标窗口·程序名=game.exe, ROI=(提示区域),
             match_mode=contains, match_text=体力不足)
   ├─ 匹配到   → 点「确定」按钮 / 吃药
   └─ 未匹配到 → 继续打怪
```

### 2. 用正则抓一类文案
```
OcrRecognize(match_mode=regex, match_text=\d+级)
   ├─ 匹配到   → 说明界面上出现了「xx级」这类文本
   └─ 未匹配到 → 走别的分支
```
> 正则只用来**判断有没有命中**。要拿命中的具体内容（比如 `金币 123` 里的 `123`），
> 连 `text` 数据出口给下游，或用 SetVariable 记录后再处理。

### 3. 识别数字区域
```
OcrRecognize(识别范围=目标窗口, ROI=(血量区域), lang=en)
   └─ text ──→ VarSwitch(in_0) 做数值判断
```
识别**数字**用 `lang=en` 更快更准；识别**中文**用 `lang=ch`。

## 依赖与打包（重要）

OCR 引擎是**内置本地引擎**（PaddleOCR），但**不烧进 EXE**，而是放在 exe 同级的 `ocr_runtime/` 目录按需加载：

- **编辑器内运行**：直接可用（项目 venv 里已装 paddle）。
- **导出独立 EXE**：若蓝图用了本节点，导出对话框会提示，把 `ocr_runtime/` 目录放到 EXE 同级即可；**没用 OCR 的蓝图导出完全不带 OCR，体积不涨**。

## 常见问题

**Q：为什么第一次识别很慢？**
→ 引擎第一次调用要加载模型（几秒），之后常驻复用，逐条识别只要几十~几百毫秒。

**Q：识别失败走 `err` 了？**
→ 可能原因：没装 paddle（报「OCR 未安装」）、截图失败、待识别图像为空、引擎异常，
或「识别范围=目标窗口」却没定位到窗口，或匹配用的正则写得非法。看日志里的 `[OCR]` 提示。

**Q：界面上一片空白，没识别到文字，走哪条出口？**
→ `完成` + `无文字`。这是**正常结果**，不是失败：截图和引擎都没问题，只是没找到文字。
要区分「没文字」和「没匹配到」，把 `无文字` 与 `未匹配到` 分别接到不同处理即可。

**Q：自己截图模式设了「目标窗口」，窗口没开会怎样？**
→ 直接走 `err`（失败），**不会退化成截全屏去识别**。否则 `roi` 坐标口径就错了，识别到的可能是屏幕别处的文字。

**Q：能不能把整屏文本发给外部接口处理？**
→ 可以连 `text` 数据出口。注意当前**网络请求节点只有执行入口、没有数据入参**，
它的 URL / body 里只能插值 `{变量}`；而本节点已不再写变量，所以要直接发送识别文本，
需要先有一条把数据喂进网络请求的通道（待补）。

**Q：怎么识别得更准？**
→ ROI 框得越小越准；纯数字用 `en`；截图要清晰、对比度高，别截到半透明/毛玻璃背景。
