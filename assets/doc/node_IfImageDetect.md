# 👀 IfImageDetect · 检测

> 当下就检查好几张图是不是都在屏幕上~完全求值全中才走「检测到」，短路缺一张就立马否决，一真即真（逻辑或）只要撞见任意一张中就喊「检测到」；只瞅当下这一眼，不会等太久哟。

---

## 节点外观

- **分类**：👁 感知
- **配色**：橙 (#ef6c00 / #ff9800)
- **短名**：`if_img`

---

## 端口

### 输入
| 名称 | 类型 | 标签 | 说明 |
|------|------|------|------|
| `in_exec` | ▶ 执行 | ▶ | 上游触发 |

### 输出
| 名称 | 类型 | 标签 | 说明 |
|------|------|------|------|
| `yes` | ▶ 执行 | 检测到 | 符合条件（按求值模式判定为命中）→ 走这里 |
| `no` | ▶ 执行 | 未检测到 | 不符合条件 → 走这里 |
| `err` | ▶ 执行 | 失败 | **仅**「范围=目标窗口」但目标窗口没定位到时走这里，不会退化成全屏去检测 |

> 💡 **和 FindImage 的区别**：FindImage 是"在一段时间内反复重试找，找到走 `found`、没找到走 `not_found`"；IfImageDetect 是"当下瞅一眼立刻给「检测到 / 未检测到」二选一，不重试"。FindImage 适合"必须等到按钮出现再操作"，IfImageDetect 适合「当前界面是不是这个页面？」做条件分支判断。
>
> ⚠ 注意：`err` 只管「目标窗口没定位到」这种环境/配置错误。**参考图没匹配上**是正常判定结果，走 `no`「未检测到」（或按求值模式的规则），不算失败。

## 参数一览

| 参数 | 编辑器 | 默认值 | 说明 |
|------|--------|--------|------|
| `range_mode` | 下拉 | `window` | 检测范围：`window` 目标窗口 / `fullscreen` 全屏 |
| `target_title` | 文本 | `""` | 仅「目标窗口」范围生效：窗口标题子串（支持 `{变量}`）；点「🎯 拾取目标窗口」可自动填 |
| `target_exe` | 文本 | `""` | 仅「目标窗口」范围生效：程序名子串 |
| `target_class` | 文本 | `""` | 仅「目标窗口」范围生效：窗口类名精确匹配 |
| `match_strategy` | 下拉 | `hybrid` | 匹配算法：智能混合 / 模板 / 灰度（同 FindImage） |
| `threshold` | 小数 | `0.9` | 匹配阈值（0.3~1.0），全代码层统一默认 0.9 |
| `eval_mode` | 下拉 | `complete` | 求值模式：完全求值 / 短路模式 / 一真即真 |
| `images_json` | 文本 | `"[]"` | 参考图列表 JSON 数组；Inspector 中提供可视化 UI，不用手填 |

> 💡 **目标窗口与「📷 截图新增一张」联动（仅制作参考图时的便利）**：若已配置并拾取到目标窗口，
> 截图时框选范围会自动限定在该窗口内（窗口外点不进去、拖到边界自动贴边）。若配置了但当前找不到该窗口，
> 框选工具会回退成全屏框选并打日志提示——这只是**画框工具的制作便利**；
> **运行时**范围选「目标窗口」却找不到窗口，是直接走 `err`，绝不回退全屏。

## 三种求值模式 eval_mode

| 模式 | 逻辑 | 说明 |
|------|------|------|
| **complete 完全求值** | AND 全匹配 | 不管中间有没有失败，所有参考图都会检测一遍，日志输出每张得分（便于调试）；全部匹配才走「检测到」。**默认模式。** |
| **short_circuit 短路模式** | AND 一假即假 | 从左到右依次检测，只要有一张不匹配 → 立刻返回「未检测到」，省时间 |
| **or_true 一真即真** | OR 一真即真 | 任意一张匹配成功 → 立刻返回「检测到」；全部都不匹配才走「未检测到」 |

> ⚠ 完全模式下，如果**没有添加任何参考图**（空集），将直接走「未检测到」分支。

---

## 检测范围 range_mode

### window 目标窗口（推荐）
- 只在「目标窗口」定位到的那个窗口范围内检测，确保所有模板都在**同一个窗口**里找到，避免跨窗口误匹配
- 窗口从哪来：本节点自己的「目标窗口」定位参数（`target_title` / `target_exe` / `target_class`，**至少填一个**）
- ⚠ 定位不到窗口 → 直接走 `err` 失败出口，**不会退化成全屏去检测**

### fullscreen 全屏
- 在整块屏幕上检测，可能把不同窗口里长得像的图案误判为"都在"

## 可视化添加参考图

不用手填 images_json，属性面板里有专门的 UI：

1. 点「➕ 添加检测图」
2. 每个检测图都有自己的缩略图、模板路径、独立阈值（可选，没填就用节点全局 threshold）
3. 每个检测图都能点「📸 截取」或「📂 导入」选图 —— 图片会自动存进
   **`res/<当前蓝图所在目录>/`**（例如蓝图在 `script/组件1/`，图片就落在 `res/script/组件1/`），
   面板里存的 `path` 是相对工程根的路径，工程整体搬走也不失效
4. 可以点「上移/下移」调整检测顺序（对短路/一真即真模式有意义）
5. 点「🗑 删除」去掉某一张（残留的图片文件可用资源面板的 🧹 清理未使用资源 收掉）

images_json 里面每一项结构示例（`path` 是相对工程根的路径，`b64` 是给画布/网格显示用的缩略图）：
```json
[
  {"b64":"...(base64缩略图)...","w":120, "h":40, "path":"res/script/组件1/ifimg_20260914_101500_a1b2c3.png"},
  {"b64":"...","w":80,"h":30,"path":"res/script/组件1/ifimg_20260914_101502_d4e5f6.png","threshold":0.95}
]
```
> 匹配时**优先用 `path` 指向的全分辨率原图**，`b64` 只是预览；两者都在时以原图为准，匹配更准。

## 测试匹配按钮

右侧属性面板有「🔍 测试匹配」按钮，会按节点当前的**检测范围**（目标窗口内 / 整屏）现场跑一遍所有参考图并列出每张得分：

- 范围=目标窗口时，会先定位目标窗口；**定位不到会直接弹窗提示并中止**，绝不悄悄改成全屏检测（与运行时口径一致）。
- 范围=全屏时，在整屏上检测。

## 典型用法

### 1. 判断当前是不是「游戏主菜单」页面
完全模式 AND，页面上三个按钮都有才走「检测到」：
```
IfImageDetect：
  eval_mode  = complete（完全求值，三张全中才算「检测到」）
  range_mode = window
  target_exe = game.exe
  参考图：
    ① 「开始游戏」按钮模板
    ② 「设置」按钮模板
    ③ 「退出」按钮模板

连线：
  检测到   → 说明在主菜单 → 点击开始游戏
  未检测到 → 可能在登录界面 → 其他处理
  失败     → 目标窗口没开 → 记录/提示
```

### 2. 三种弹窗任意出现一种就点关闭（OR 逻辑）
```
IfImageDetect：
  eval_mode = or_true（一真即真）
  参考图：
    ① 「每日签到」关闭按钮
    ② 「活动公告」关闭按钮
    ③ 「版本更新」关闭按钮

连线：
  检测到   → 有弹窗 → 用 Sequence(or_true) 找对应按钮点掉
  未检测到 → 没弹窗 → 跳过
```

### 3. 快速判断某个提示有没有弹出来（短路省时间）
```
IfImageDetect：
  eval_mode = short_circuit
  参考图：①「提示-体力不足」②「提示-背包已满」
```
→ 体力不足那张一出来就立刻判定「检测到」，不用等背包已满也检测一遍，省时间。

## 常见问题

**Q：为什么 FindImage 有重试/超时，IfImageDetect 没有？**
→ 定位不同：FindImage 是「等出现」；IfImageDetect 是「当下判断」。如果想「等 5 秒看会不会出现」，用 Loop 包一层 IfImageDetect，走「检测到」就 break，5 秒超时按「未检测到」处理。

**Q：20 张图同时检测会不会特别慢？**
→ 会。建议一屏内一次检测控制在 5~8 张以内，或者用短路/一真即真模式尽早退出。检测时间 ≈ 张数 × 单张平均耗时。

**Q：明明设了「目标窗口」，为什么有时会匹配到别的窗口里的相似图案？**
→ 不会。范围=目标窗口时只在那个窗口内检测；而且定位不到该窗口会直接走 `err`，不会退回全屏乱匹配。

**Q：images_json 是字符串还是数组？**
→ 节点参数里存的是**字符串化的 JSON**（因为 ParamDef 里 EDITOR_STRING）；运行时内部会解析成 list，解析失败就视为空数组 []，不会报错。
