# 🤫 StillnessDetect · 静止

> 盯着屏幕上一块区域看~画面安安静静不变就走yes，等太久还在动就超时走no，用来等加载结束最合适啦。

---

## 节点外观

- **分类**：👁 感知
- **配色**：深橙 (#d84315 / #ff7043)
- **短名**：`if_static`

---

## 端口

| 侧 | 名称 | 类型 | 标签 | 说明 |
|----|------|------|------|------|
| 入 | `in_exec` | ▶ 执行 | ▶ | 上游触发 |
| 出 | `yes` | ▶ 执行 | 静止 | ROI 区域画面连续静止 N 秒 → 走这里 |
| 出 | `no`  | ▶ 执行 | 超时 | 超过最大超时画面还在变化 → 走这里 |
| 出 | `err` | ▶ 执行 | 失败 | **仅**「范围=目标窗口」但目标窗口没定位到时走这里，不会退化成全屏去检测 |

> ⚠ `err` 只管「目标窗口没定位到」这种环境/配置错误；画面一直动导致超时属于正常判定，走 `no`。

---

## 参数一览

| 参数 | 编辑器 | 默认值 | 说明 |
|------|--------|--------|------|
| `range_mode` | 下拉 | `window` | 检测范围：`window` 目标窗口 / `fullscreen` 全屏 |
| `target_title` | 文本 | `""` | 仅「检测范围=目标窗口」时生效：窗口标题子串（支持 `{变量}`）；点「🎯 拾取目标窗口」可自动填 |
| `target_exe` | 文本 | `""` | 仅「检测范围=目标窗口」时生效：程序名子串（如 notepad.exe），支持 `{变量}` |
| `target_class` | 文本 | `""` | 仅「检测范围=目标窗口」时生效：窗口类名精确匹配，支持 `{变量}` |
| `roi` | 四元组 | `(0,0,0,0)` | ROI 区域 `(x,y,w,h)`（相对检测范围左上角），Inspector 里点「🖱 框选ROI」按钮可视化选（与截图/文字节点同款） |
| `roi_preview_b64` | 文本 | `""` | ROI 缩略图（自动记录不用手填） |
| `stillness_seconds` | 小数 | `5.0` | 需要画面**持续静止**的最小秒数（0.1 ~ 600） |
| `timeout_seconds` | 小数 | `20.0` | 超时秒（1.0 ~ 3600），超过了走「超时」出口 |
| `sample_interval_seconds` | 小数 | `1.0` | 采样间隔秒（0.03 ~ 60），每隔多久截一帧做对比 |
| `diff_threshold` | 小数 | `0.01` | 帧差阈值（0.0 ~ 0.5），两帧 ROI 像素差低于该值视为"安静" |

---

## 检测范围 range_mode

### window 目标窗口（推荐）
- ROI 坐标**相对目标窗口左上角**；窗口移动，ROI 跟着移动
- 窗口从哪来：本节点自己的「目标窗口」定位参数（`target_title` / `target_exe` / `target_class`，**至少填一个**）
- ⚠ 定位不到窗口 → 直接走 `err` 失败出口，**不会退化成全屏去检测**

### fullscreen 全屏
- ROI 坐标相对**屏幕左上角**，固定不变

## 它是怎么判断"静止"的？

```
循环（每隔 sample_interval 秒截一帧）：
  ① 截 ROI 区域 → 和上一帧做像素差分
  ② 差分像素比例 < diff_threshold？
    ✅ 是：累计"连续安静时间" + sample_interval
       连续安静时间 ≥ stillness_seconds？
         → ✅ 走 yes（静止！）
    ❌ 否：连续安静时间清零，继续等
  ③ 总时间 ≥ timeout_seconds？
     → ❌ 走 no（超时，画面一直有变化）
```

## 典型用法

### 1. 等游戏加载完毕（过场动画结束）
```
StillnessDetect：
  range_mode        = window
  target_exe        = game.exe
  roi               = 选中游戏画面主区域（比如整个画面，不用太精确）
  stillness_seconds = 3.0     ← 画面连续 3 秒没变化 = 加载完了
  timeout_seconds   = 120.0   ← 最多等 2 分钟
  sample_interval   = 1.0
  diff_threshold    = 0.02    ← 小动（粒子特效）不算变化，调大一点容忍

连线：
  yes → 加载完了，可以点进入按钮
  no  → 超时了，Notify("加载超时！")
  err → 目标窗口没开（异常）
```

### 2. 等对话框不晃了再点按钮
有些弹窗打开时会有淡入动画，立刻点会点不到：
```
StillnessDetect：
  range_mode = window
  target_title = 某某弹窗标题
  roi = 对话框矩形区域
  stillness_seconds = 0.5
  timeout_seconds   = 5.0
→ yes → Mouse 点对话框内的按钮
```

### 3. 等进度条走到头
进度条本身会一直在动 → 等它**停止变化**就表示进度 100% 了：
```
StillnessDetect：
  range_mode = window
  target_class = 某某窗口类名
  roi = 进度条那条小区域
  stillness_seconds = 1.0
  diff_threshold    = 0.015
→ yes → 进度完成，点「下一步」
```

## 调参指南

### 画面有微小粒子/闪烁效果，但我想认为它是"静止"
→ 把 `diff_threshold` **调高**：0.02 → 0.03 → 0.05，直到小粒子变化不触发"还在动"。

### 对静止要求很严格（等精确的某个瞬间）
→ `diff_threshold` **调低**（0.005 左右），`stillness_seconds` 调小（0.3 左右）。

### ROI 框多大合适？
- **等加载**：框整个游戏画面（或者画面中间核心区域）
- **等某个弹窗**：只框弹窗区域（避免背景其他地方动干扰判断）
- **等某个进度条**：只框进度条那一条小矩形

→ **ROI 越小，检测越快越准**，不要每次都选全屏。

## 常见问题

**Q：画面一直有轻微变化，永远达不到静止？**
→ 两个办法：① diff_threshold 调大一点容忍；② stillness_seconds 调小（比如 0.5 秒就够了，不用连续 5 秒那么长）。

**Q：检测特别慢？**
→ sample_interval 默认 1 秒，这个就够了，不用调得太小（0.03 秒一帧会把 CPU 跑满）。ROI 选小一点也能快很多。

**Q：ROI 坐标怎么选才准确？**
→ Inspector 面板里点「📍 框选ROI区域」按钮，屏幕会变半透明，直接在目标窗口上拉框选，自动填进 roi 参数，不用手算坐标。

**Q：设了「目标窗口」但窗口没开，会怎样？**
→ 直接走 `err`（失败）出口。不会退化成全屏去瞎检测——那样 ROI 坐标口径就错了，只会得到无意义的判定。
