# ⚡ Parallel · 并行执行（多分支并发）

> 把多条分支都塞进子画布里，每条分支用线程**同时跑**，各跑各的互不等待。全部跑完走「完成」，任意一条出错走「失败」（但不打断其它分支）。双击本节点进入子画布编辑。

---

## 节点外观

- **分类**：🧠 逻辑
- **配色**：青绿 (#0E6B5C / #2DD4BF)
- **短名**：`parallel`

---

## 端口

| 侧 | 类型 | 名称 | 标签 | 说明 |
|----|------|------|------|------|
| 输入 | ▶ 执行 | `in_exec` | ▶ | 上游触发 |
| 输出 | ▶ 执行 | `out_done` | 完成 | 全部分支跑完后继续往下走 |
| 输出 | ▶ 执行 | `err` | 失败 | 至少一条分支失败时走这里（其它分支仍跑完） |

---

## 参数一览

| 参数名 | 编辑器 | 默认值 | 说明 |
|--------|--------|--------|------|
| `par_body` | （只读，自动维护） | `""` | 并行体子画布内容，双击节点进入编辑 |

> **并行分支数量不靠参数设置**：有几条分支，取决于你在子画布里放了几个「分支入口(Branch)」节点，
> 放 3 个就是 3 条分支（所以没有「分支数量」这个参数）。

---

## 核心机制

1. **子画布容器**：并行内容塞在本节点的子画布里，双击进入编辑。
   > 💡 双击进去只是「看」，不算修改：没动过任何东西时，进出子画布不会让蓝图变成「有未保存修改」。
2. **分支入口节点**：进入子画布后，从节点库里拖「分支入口(Branch)」节点。每个「分支入口」代表一条并行分支的起点，从它的 `out_exec` 往下连就是这条分支要跑的动作。
3. **并发执行**：运行时所有「分支入口」用线程同时启动，各分支独立走完自己的执行流。
4. **汇聚判定**：全部分支跑完 → 「完成」；任一条分支终结于失败语义端口（如 `err` / `fail` / `not_found`）→ 「失败」，但**不会打断其它分支**，它们仍会跑完。
5. **共享变量**：所有分支共享同一套变量（`ctx.variables`），分支间可以读写同一变量（注意并发写的竞态，建议各分支写各自的变量名）。
6. **共享系统资源（剪贴板）已自动串行**：剪贴板是系统级单例，所有碰剪贴板的操作
   （按键节点的粘贴模式、剪贴板节点的读/写/清空）共用一把**全局剪贴板锁**，会**排队执行**——
   多条分支同时粘贴时不会互相覆盖，各自粘出自己的文本。代价：这几步不再真并发，且**先后顺序不保证**。

## 典型用法

### 同时盯多个画面区域

```
主蓝图：Start → Parallel(双击进入) → 后续节点

进入 Parallel 子画布：
    分支入口#1 → 静止(等待左上角加载完成)
    分支入口#2 → 静止(等待右下角加载完成)
    分支入口#3 → 循环(每2秒找一次活动图标)

三条分支同时跑，全跑完 → 主蓝图继续。
```

## 常见问题

**Q：并行分支里能放鼠标 / 键盘操作吗？**
→ 能放，但要注意：多个分支同时操作鼠标/键盘会**互相打架**（鼠标只有一个）。并行的价值在于「等待类」操作（静止、找图、延时、网络请求等）同时进行；需要物理独占的操作（点击、拖拽）建议放到串行段。

**Q：并行分支里用按键节点粘贴文本，会互相覆盖吗？**
→ 不会。粘贴是「写剪贴板 → Ctrl+V」，内部用一把**全局剪贴板锁**把这两步绑成不可分割的一段，
多条分支会排队粘贴，每条粘出的都是自己的文本（修复前会出现「所有分支都粘出最后写入的那份内容」）。
但**顺序不保证**：谁先拿到锁谁先粘。若顺序有意义（例如往同一个输入框按固定次序打字），请放到「顺序执行」里。

**Q：在并行分支里往同一个输入框打字，结果乱序 / 串行？**
→ 键盘输入本身是发按键事件，多分支同时打会交叠；粘贴模式因为要独占剪贴板，会**排队**，
所以看起来是「一条打完再打下一条」。需要严格次序的场景请用「顺序执行」，并行只适合各操作互不依赖的情况。

**Q：一条分支失败了会影响其它分支吗？**
→ 不会。失败的判定只在最后汇聚时生效：只要有分支失败，本节点走「失败」出口，但其它分支仍会正常跑完。

**Q：和「顺序执行(Sequence)」的区别？**
→ 顺序执行是一条一条串行跑；并行执行是多条同时跑。内容都用子画布容器承载，交互一致。
