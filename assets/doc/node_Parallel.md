# ⚡ Parallel · 并行执行（多分支并发）

> 把多条分支都塞进子画布里，每条分支用线程**同时跑**，各跑各的互不等待。
> **不需要接「结束」节点** —— 分支跑到最后一个节点就算收尾；只有分支里**节点执行报错**才走「失败」（且不打断其它分支）。
> 想让整个并行提前收工？在某条分支里放一个「**退出并行**」节点即可（默认走「完成」，勾上「标记为失败」则走「失败」）。
> ⚠ 调试时并行**默认是黑盒**：断点 / 单步 / 运行高亮只停在并行节点本身，不进并行体。
> 典型场景「一个分支跑主逻辑 + 其它分支跑守护/保活」→ 勾上「**调试主线程**」参数，就能在主线程分支里打断点、单步、看高亮，其它分支照常跑。
> **能用串行就别用并行**。
> 双击本节点进入子画布编辑。

- **短名**：`parallel`

## 端口

| 侧 | 类型 | 名称 | 标签 | 说明 |
|----|------|------|------|------|
| 输入 | ▶ 执行 | `in_exec` | ▶ | 上游触发 |
| 输出 | ▶ 执行 | `out_done` | 完成 | 全部分支正常跑完；或某条分支走了**未勾「标记为失败」的退出节点**提前结束 |
| 输出 | ▶ 执行 | `err` | 失败 | 至少一条分支里有节点**执行报错**（抛异常、死循环）；或退出节点勾了「标记为失败」；**其它分支仍会跑完** |

---

## 参数一览

| 参数名 | 编辑器 | 默认值 | 说明 |
|--------|--------|--------|------|
| `par_body` | （只读，自动维护） | `""` | 并行体子画布内容，双击节点进入编辑 |
| `debug_main` | ☑ 调试主线程 | 关 | 开启后允许调试并行体：断点/单步/运行高亮只作用在「主线程分支」上，**其它分支不受调试暂停影响、照常运行**。不勾 = 调试黑盒（断点只停在并行节点本身） |

> **并行分支数量不靠参数设置**：有几条分支，取决于你在子画布里放了几个「分支入口(Branch)」节点，
> 放 3 个就是 3 条分支（所以没有「分支数量」这个参数）。

## 子画布专用节点

进入并行体子画布后，节点库会**额外**给出两个只能在这里用的节点（回根图就看不到）：

| 节点 | 短名 | 作用 | 参数 |
|------|------|------|------|
| **分支入口** | `branch` | 一条并行分支的起点，从它的 `out_exec` 往下连分支内容 | `is_main`（主线程分支，默认关；有且只能有一个，都不勾时默认第一个分支入口） |
| **退出并行** | `exit_par` | 跑到它就**中止整个并行结构**，其它分支跑完手上那个节点后退出 | `as_failure`（标记为失败，默认关） |

**「退出并行」的 `as_failure`**：不勾（默认）→ 本节点整体走「**完成**」出口；
勾上 → 整体走「**失败**」出口（同时还有分支真报错时，失败优先）。

## 核心机制

1. **子画布容器**：并行内容塞在本节点的子画布里，双击进入编辑。
   > 💡 双击进去只是「看」，不算修改：没动过任何东西时，进出子画布不会让蓝图变成「有未保存修改」。
2. **分支入口节点**：进入子画布后，从节点库里拖「分支入口(Branch)」节点。每个「分支入口」代表一条并行分支的起点，从它的 `out_exec` 往下连就是这条分支要跑的动作（**末尾不需要接「结束」节点**）。
   > 💡 进入并行体子画布后，左侧节点库会**额外**出现「分支入口」和「退出并行」两个节点 ——
   > 它们只在这个子画布里可用（回到根图就看不到了）。
3. **并发执行**：运行时所有「分支入口」用线程同时启动，各分支独立走完自己的执行流。
4. **汇聚判定**：判定口径与 **Sequence / Loop 完全一致** —— **只看有没有节点执行报错**（抛异常、死循环）；
   另外，某条分支走了**勾上「标记为失败」的退出节点**也算失败。
   都没有 → 「完成」；有分支报错 / 退出标记为失败 → 「失败」（**不打断其它分支**，它们仍会跑完）。
   ⚠ 分支跑到最后一个节点、末尾出口悬空、**没接「结束」节点** —— 都算正常收尾，**不算失败**；
   中途走了 `not_found` / `no` / `err` 这类端口也**不算失败**（那是它自己的正常分支）。
5. **提前结束整个并行（退出并行）**：在某条分支里放一个「**退出并行**」节点，就会
   **中止整个并行结构** —— 其它分支收到停止信号后，跑完手上那个节点就退出。
   > ⚠ Python 线程没法强杀，所以是「**节点边界上协作式退出**」，不是中途硬切；
   > 正在做的一次长等待（比如 10 秒的静止）会先走完。
   >
   > **走哪个出口**由「退出并行」节点的参数 `as_failure`（标记为失败）决定：
   > 不勾（默认）→ 「**完成**」；勾上 → 「**失败**」。
   > 如果同时还有分支真的报错，那「失败」优先。
   >
   > 💡 老的「**跳出循环(Break)**」节点放在并行分支里也能达到同样效果（同样受「标记为失败」控制），
   > 但语义上请优先用「退出并行」。
   >
   > 只想结束**自己那条分支**、不动别人？用「**再次循环(Continue)**」—— 单条分支没有"下一轮"，
   > 它就是「本分支到此为止」，其它分支照跑。
6. **共享变量**：所有分支共享同一套变量（`ctx.variables`），分支间可以读写同一变量（注意并发写的竞态，建议各分支写各自的变量名）。
7. **共享系统资源（剪贴板）已自动串行**：剪贴板是系统级单例，所有碰剪贴板的操作
   （按键节点的粘贴模式、剪贴板节点的读/写/清空）共用一把**全局剪贴板锁**，会**排队执行**——
   多条分支同时粘贴时不会互相覆盖，各自粘出自己的文本。代价：这几步不再真并发，且**先后顺序不保证**。
8. **调试口径：默认黑盒，可开启「调试主线程」（重要）**：
   - **默认（不勾「调试主线程」）**：断点 / 单步 / 运行高亮都**只停在并行节点本身**，不进入并行体——
     并行体里节点上的断点标记不生效；单步（⏭）点一下 = 整个并行一口气跑完；
     运行高亮不跟进来，画布停在上一层，并行节点一直亮到收工。
   - **勾上「调试主线程」**：允许在并行体里调试——断点 / 单步 / 运行高亮只作用在**主线程分支**上
     （画布会跟着钻进并行体，停在断点节点上），**其它分支不受调试暂停影响、照常运行**——
     这正是「一个分支跑主逻辑 + 一个分支跑守护/保活」的调试姿势：断在主逻辑上看变量，
     守护线程不会被暂停卡死。
   - **主线程分支是哪条**：并行体里勾了「主线程分支」的那个分支入口，**有且只能有一个**
     （编辑器里勾一个会自动取消其它；万一手工改出多个，运行时只认第一个并打 WARN）；
     一个都没勾 → 默认第一个分支入口。主线程分支的日志带 `[并行分支·主线程]` 标记。
   - 非主线程分支里的断点标记**不生效**（黑盒不变）。
   - ⚠ **建议减少使用并行**：分支共享鼠标 / 键盘 / 剪贴板，容易互相打架（见下面 FAQ）。
     **能用串行就别用并行**，只把真正需要同时等待的操作（静止 / 找图 / 延时 / 网络请求）放进来。

## 典型用法

### 同时盯多个画面区域

```
主蓝图：Start → Parallel(双击进入) → 后续节点

进入 Parallel 子画布：
    分支入口#1 → 静止(等待左上角加载完成)
    分支入口#2 → 静止(等待右下角加载完成)
    分支入口#3 → 循环(每2秒找一次活动图标)

三条分支同时跑，全跑完 → 主蓝图继续。（末尾不用接「结束」节点）
```

### 谁先到位就收工（退出并行）

```
进入 Parallel 子画布：
    分支入口#1 → 循环(等弹窗A出现) → 退出并行
    分支入口#2 → 循环(等弹窗B出现) → 退出并行

哪条分支先等到，就在那里「退出并行」→ 整个并行结构立刻提前收尾，
另一条分支跑完手上那个节点后退出，主蓝图继续往下走。

（默认走「完成」出口；若想按失败处理，把「退出并行」的「标记为失败」勾上。
  老的「跳出循环」节点放在分支里也一样能中止，但推荐用「退出并行」。）
```

## 常见问题

**Q：并行分支里能放鼠标 / 键盘操作吗？**
→ 能放，但要注意：多个分支同时操作鼠标/键盘会**互相打架**（鼠标只有一个）。并行的价值在于「等待类」操作（静止、找图、延时、网络请求等）同时进行；需要物理独占的操作（点击、拖拽）建议放到串行段。

**Q：并行分支里用按键节点粘贴文本，会互相覆盖吗？**
→ 不会。粘贴是「写剪贴板 → Ctrl+V」，内部用一把**全局剪贴板锁**把这两步绑成不可分割的一段，
多条分支会排队粘贴，每条粘出的都是自己的文本（修复前会出现「所有分支都粘出最后写入的那份内容」）。
但**顺序不保证**：谁先拿到锁谁先粘。若顺序有意义（例如往同一个输入框按固定次序打字），请放到「顺序执行」里。

**Q：在并行分支里往同一个输入框打字，结果乱序 / 串行？**
→ 键盘输入本身是发按键事件，多分支同时打会交叠；粘贴模式因为要独占剪贴板，会**排队**，
所以看起来是「一条打完再打下一条」。需要严格次序的场景请用「顺序执行」，并行只适合各操作互不依赖的情况。

**Q：一条分支出错了会影响其它分支吗？**
→ 不会。判定只在最后汇聚时做：只要有分支里节点执行报错，本节点就走「失败」出口，但其它分支仍会正常跑完。

**Q：「没找到」这类分支会被判失败吗？**
→ 不会。判定只看**有没有节点执行报错**。找图没命中走 `not_found` 属于它自己的正常分支，不算失败。
同理，分支跑到末尾没接「结束」节点，也只是正常收尾。

**Q：一条分支走到「结束」节点，能顺带把其它分支也叫停吗？**
→ **不能**。「结束(End)」只结束**它自己那条分支**，其它分支照跑；整个并行仍然要等所有分支都收尾才汇聚。

**Q：我在并行体里的节点上打了断点，为什么运行时完全不停？**
→ 默认如此（调试黑盒）：并行是多线程并发，直接逐节点暂停会把所有分支搅在一起，
所以**断点 / 单步 / 运行高亮都只作用在并行节点本身**：
断点请打在「并行执行」节点上（停住时整个并行还没开始跑）；
单步点一下⏭ = 整个并行一口气跑完。想细看并行体里的执行过程，看日志面板——
每个分支节点都会打 `[Node▶] … [并行分支]` 日志。

**Q：我需要一个分支跑主逻辑、其它分支跑守护（保活），调试时怎么断点？**
→ 勾上并行节点的「**调试主线程**」参数：断点 / 单步 / 运行高亮会进入**主线程分支**
（默认第一个分支入口；在分支入口节点上勾「主线程分支」可更换，有且只能有一个），
断在哪就能看变量、看截图证据，**其它分支完全不受影响、照常运行**——守护线程不会因为
你调试主逻辑而停摆。注意：只有主线程分支能这么调，其它分支里的断点标记不生效。
想中止整个并行结构，用「**退出并行**」节点（老的「跳出循环(Break)」放在分支里也行）。

**Q：和「顺序执行(Sequence)」的区别？**
→ 顺序执行是一条一条串行跑；并行执行是多条同时跑。内容都用子画布容器承载，交互一致，
「完成 / 失败」的判定口径也和 Sequence、Loop 完全一样：**只有节点执行报错才算失败**，都不要求接「结束」节点。
