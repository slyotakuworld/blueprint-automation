# ⚖️ VarSwitch · 条件判断

> 一条条检查汝写的条件~全部都对上了就走「满足」，只要有一条不对就走「不满足」。

---

## 节点外观

- **分类**：🧠 逻辑
- **配色**：灰红 (#57606A / #F78166)
- **短名**：`var_switch`

---

## 端口

### 输入
| 名称 | 类型 | 标签 | 说明 |
|------|------|------|------|
| `in_exec` | ▶ 执行 | ▶ | 上游触发 |
| `in_0`、`in_1`… | ○ 数据 | #1 输入、#2 输入… | 动态数据输入端口（0 ~ 20 个），通过 `num_data_inputs` 调整 |

### 输出
| 名称 | 类型 | 标签 | 说明 |
|------|------|------|------|
| `yes` | ▶ 执行 | 满足 | 所有条件全部满足 → 走这里 |
| `no` | ▶ 执行 | 不满足 | 任意一条不满足 → 走这里 |

---

## 参数一览

| 参数名 | 编辑器 | 默认值 | 必填 | 说明 |
|--------|--------|--------|------|------|
| `num_data_inputs` | 整数 | `1` | - | 数据输入端口数（0 ~ 20），改了之后左侧出现对应数量的绿色端口 |
| `cases` | 多行文本 | `""` | - | 批量条件，每行一条，全部 AND 逻辑（同时满足） |

---

## cases 条件语法

### ① 标准写法：`变量名 运算符 值`
```
hp >= 30
hp <= 100
score >= 60
level > {min_level}
```

### ② 简写语法（连了 in_0 时推荐）
行首直接写运算符，左值自动 = `__INPUTS__0`（第一个数据端口）：
```
== 1              → __INPUTS__0 == 数字 1
== {id}           → __INPUTS__0 == 变量 id
!= {exclude}      → __INPUTS__0 != 变量 exclude
>= {min_score}    → __INPUTS__0 >= 变量 min_score
```
→ 不用每条都重复写变量名，非常方便！

### ③ 多端口完整写法（**一行一条，逐行分开写**）
```
__INPUTS__0 >= {min_score}
__INPUTS__1 != {exclude_status}
```
→ 这两行是 AND 关系（同时满足才走 yes），**不要写成 `__INPUTS__0 >= {min_score} AND __INPUTS__1 != ...` 这样一行塞两个**：
本节点不支持行内 `AND`/`OR`，写了会被判成格式错误（因为整行右半段会被当成「值」，既不可能相等、又不会报错）。

## 支持的运算符

| 运算符 | 含义 | 示例 |
|--------|------|------|
| `==` | 等于 | `status == "ok"`、`count == 0` |
| `!=` | 不等于 | `name != "赫萝"` |
| `>` | 大于 | `score > 60` |
| `<` | 小于 | `hp < 30` |
| `>=` | 大于等于 | `lv >= 10` |
| `<=` | 小于等于 | `time <= 30` |

---

## 右边的值怎么写？

| 值类型 | 写法示例 | 说明 |
|--------|----------|------|
| 数字 | `1` / `3.14` / `-5` | 直接写，不用加引号 |
| 字符串 | `"hello"` / `'赫萝'` | 必须加引号（单双都行） |
| 布尔 | `true` / `false` | 小写 |
| 变量引用 | `{hp}` / `${min_level}` | 花括号，会被替换成变量实际值 |
| 表达式 | `{= {a} + {b}}` | 做计算 |

## ⚠ 重要注意事项

### 1. 条件之间是 AND（全部满足才算 yes）
```
hp >= 30
hp <= 100
score >= 60
```
三条必须**同时满足**才走 yes；只要有一条不满足就走 no。

### 2. 比较运算符（> < >= <=）只支持数值！
```
hp > 30        ✅ hp 是数字
"30" > 20      ❌ 左边是字符串，直接返回 False
status > "ok"  ❌ 字符串不支持大小比较，返回 False
```
字符串比较用 `==` / `!=`。

### 3. 条件引用变量时要加花括号
```
✅ hp >= {min_hp}
❌ hp >= min_hp   （会把 min_hp 当字符串字面量，不是变量）
```

### 4. 注释和空行会被忽略
```
# 这是注释，不会被解析
// 这也是注释

hp >= 30     ← 空行上面的注释没问题
```

### 5. 不支持行内 `AND` / `OR`
条件的 AND 是「**行与行之间**」自动生效的，一行里只能有一个比较：

```
✅ 正确（两行）
hp >= 30
hp <= 100

❌ 错误（一行塞两个）
hp >= 30 AND hp <= 100
```

写成后面这种会被判成**格式错误**（右半段会被当成值 `30 AND hp <= 100`，永远对不上）。
需要 OR（满足其一即可）时，串两个条件判断节点：第一个的 `不满足` → 第二个的 `▶`。

### 6. 左值只能是裸变量名，不能花括号
```text
✅ __INPUTS__0 >= {min_score}
✅ hp >= 30
✅ 血量 >= 30         （变量名允许汉字，与「设置变量」口径一致）
❌ {hp} >= 30        （左值不能写 {…}）
❌ my-var >= 30      （变量名不能含横杠；数字开头、带空格也不行）
```

## 运行时怎么排错（看日志）

条件写错时**不会静默走不满足**了，运行日志里会有明确的 WARN，三种典型情况：

| 日志提示 | 说明 |
|----------|------|
| `有 N 条条件语法非法，这些行会被忽略：第X行「…」缺少合法运算符…` | 那一行语法不合法（例如少写一个 `=`），被跳过 |
| `没有可用条件 → 直接走「不满足」出口（条件行全部语法非法/条件设置为空）` | 一条合法条件都没有，直接走 no |
| `有 N 条条件可能写错：第X行「…」右侧 {xxx} 变量不存在、插值未生效` | 变量名拼错了。**最典型的是把端口值写成 `{__input__0}`** —— 正确的全大写写法是 `{__INPUTS__0}` |

> 端口值在条件里的唯一正确写法是 `{__INPUTS__0}`（第1个端口）、`{__INPUTS__1}`（第2个）…
> `INPUTS` 必须**全大写**、两侧各两条下划线。写成 `{__input__0}` 时变量不存在，
> 花括号不会被替换（会原样当字符串比较），恒不相等 —— 现在这种写法会在日志里报 WARN 点出来。

## 典型用法

### 1. 判断游戏 HP 是否正常
```
cases：
  hp >= 30
  hp <= 100

连线：
  yes → 继续正常流程
  no  → Notify("HP 不正常！") → Mouse(点加血按钮)
```

### 2. 判断 Command 退出码
先把 Command.exit_code（绿色数据端口）连到 VarSwitch 的 in_0。

```
cases（简写语法）：
  == 0
```
→ 退出码 0 就是成功，非 0 走 no。

### 3. 多条件组合
```
cases：
  level >= {min_level}
  status == "active"
  coins >= 100
```
→ 等级达标、状态是激活、金币 ≥100，同时满足才算「符合条件」。

## 常见问题

**Q：支持 OR 吗？一条不满足想试下一条？**
→ 目前 cases 里只有 AND。需要 OR 逻辑可以串两个 VarSwitch：第一个走 no 时接到第二个 VarSwitch 的 in_exec，就实现"条件A 或 条件B"了。未来版本会加 OR 模式。

**Q：输入端口连了一个字符串，想跟数字比较？**
→ 先用 SetVariable 里的表达式 `{= int({__INPUTS__0})}` 转成数字，再判断。

**Q：条件明明看着对，为什么总是走「不满足」？**
→ 按顺序排三件事：① 看运行日志有没有黄色 WARN（八成那里已经点出来了）；
② 检查变量名有没有 `{__INPUTS__0}` 写成 `{__input__0}` 这种大小写问题；
③ 检查是不是把两条条件写在了一行用了 `AND`。

**Q：端口值怎么在条件里引用？**
→ 只有一种写法：`{__INPUTS__0}`（第1个数据端口）、`{__INPUTS__1}`（第2个）…。
`INPUTS` 全大写、两侧双下划线。连了第 1 个端口时还能用简写语法，行首直接写运算符即可。
