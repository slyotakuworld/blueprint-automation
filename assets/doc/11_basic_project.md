# 📁 项目管理

> 🗂 **蓝图的所有管理动作都在左侧「工程资源」面板里做**（像 Cocos Creator 的资源面板一样）：
> 新建、打开、重命名、删除、改类型、清理资源，全在面板上点右键或点顶部小按钮完成。
> 顶栏「工程 ▾」只负责**工程级**操作：新建工程 / 打开工程 / 最近工程。

---

## 🗂 工程资源面板（左侧第一栏）

面板顶部 5 个小按钮：

| 按钮 | 作用 |
|------|------|
| ＋蓝图 | 在**当前选中的文件夹**里新建空白普通蓝图（没选中则建在工程根） |
| ＋组件 | 在**当前选中的文件夹**里新建空白组件蓝图（组件放哪由你决定） |
| 📁 | 在当前选中的文件夹里新建子文件夹 |
| 🧹 | 清理没有被任何蓝图引用的图片资源（见下方「清理未使用资源」） |
| 🔄 | 手动刷新资源树（一般用不到，见下方「自动刷新」） |

**双击**蓝图文件 = 打开它编辑；**双击**文件夹 = 展开/折叠；当前正在编辑的蓝图前面会有 📌 并加粗显示。

### 🗺 普通蓝图 vs 🧩 组件蓝图（一眼可辨）

蓝图分两种**类型**，资源树里用图标 + 颜色 + 前缀同时标出来，不用点开就能分清：

| 显示 | 类型 | 含义 |
|------|------|------|
| 🗺 名称（蓝色） | 普通蓝图 | 一般从「Start」跑到底的流程 |
| 🧩 [组件] 名称（橙色） | 组件蓝图 | 可以被「调用组件」节点复用的蓝图 |

- 面板底部常驻图例：`🗺 蓝图 🧩 组件 🖼 资源`
- **类型和目录无关**：蓝图放在哪个目录由你决定，放哪儿都不影响它的类型
- **右键任意蓝图 → 🧩 设为组件蓝图 / 🗺 设为普通蓝图**，随时切换
- 组件蓝图才会出现在「调用组件」节点的下拉列表里

> 💡 想怎么组织目录就怎么组织。例如在工程根建 `script/组件1/`，
> 把组件蓝图都建在里面，磁盘上就是 `工程根/script/组件1/xxx.bp.json`。

### 🕘 最近打开

资源树最上方会出现「🕘 最近打开」分组（打开过蓝图之后才有），列出最近编辑的 10 张蓝图，
点一下就能切过去——比在目录里翻文件夹快得多。切换工程时该列表会跟着换。

### 🔄 自动刷新

面板会**自动盯着工程目录**：在外面新建/删除了文件、改了文件夹，资源树会自己更新
（做了防抖，批量操作也只刷新一次），一般不需要手动点 🔄。

### 🖱 拖蓝图到画布

把资源树里的 `.bp.json` 直接**拖到画布上**：

- 拖到空白处 → 生成一个「调用组件」节点并自动填好引用
- 拖到已有的「调用组件」节点上 → 换成这张蓝图
- 拖的如果还是「普通蓝图」，日志里会提醒你一声；右键把它设为组件蓝图就不会再提示

**右键菜单**（对着文件 / 文件夹 / 空白处右键）：

- 新建蓝图 / 新建组件 / 新建文件夹
- 打开蓝图
- 🧩 设为组件蓝图 / 🗺 设为普通蓝图（按当前类型反向显示）
- ✏ 重命名…（重命名组件时，所有引用它的蓝图会被**自动同步**改好，不用手动修）
- 🗑 删除（多选可批量删；删除组件前会提示有多少处引用指向它；删除走**回收站**，可恢复）
- 🧹 **清理未使用资源…**（见下）
- 🔗 **谁引用了它…**（对蓝图文件可用，见下）
- 📂 在资源管理器中定位 / 打开文件夹
- 📋 复制完整路径

### 🧹 清理未使用资源

蓝图用到的图片（截图模板、导入的参考图）会自动存进 **`res/` 目录**，并且**按蓝图所在目录镜像**：

```
工程根/
├── script/组件1/登录.bp.json      ← 蓝图
└── res/script/组件1/tpl_xxx.png   ← 它用到的图片
```

这样资源跟着蓝图走，一个目录连蓝图带资源一起搬移/删除都很干脆。

- **扫描范围**：`res/` 与 `templates/`（不动 `screenshots/` 与 `cache/`）
- **判定口径**：整张蓝图 JSON 里出现过、并且文件真实存在的图片，才算「被引用」——与导出打包口径完全一致
- 面板点 🧹（或右键 → 清理未使用资源…）→ 列出所有没人引用的图片及占用空间 → 确认后**移入回收站**（可恢复），并顺手收掉空目录

### 🔗 谁引用了它

在资源树里右键任意蓝图 →「🔗 谁引用了它…」，会列出**整个工程里所有引用了它的地方**：
哪张蓝图、在哪个子画布、哪个节点（子画布里的引用也一并列出）。双击条目即可跳到那张蓝图。

- 删组件、改组件名前先看一眼，心里有数
- 改名/删除时编辑器本来也会自动同步引用并提示引用数量，这个面板是给你「自己查」用的

## 新建蓝图

1. 左侧「🗂 工程资源」面板 → 先在树里**选中目标文件夹**（可选，不选就建在工程根）
2. 点「＋蓝图」（普通）或「＋组件」（组件蓝图），也可以右键文件夹 → 新建
3. 弹出输入框 —— 输入名称，文件直接创建在该目录下（扩展名 .bp.json）
4. 画布上自动出现绿色「Start」节点，可以直接开始拖节点啦

> 💡 为什么一新建就写盘？
> 因为赫萝想给你一种「蓝图正在被创建」的踏实感 🍎，不会因为忘存、闪退导致辛苦搭的蓝图丢了。

---

## 打开蓝图

任选：
1. 左侧「🗂 工程资源」面板 → **双击**蓝图文件
2. 左侧面板右键蓝图 → 打开蓝图
3. 顶栏「工程 ▾ → 最近工程」→ 点列表里的工程（切工程）
4. **启动软件会弹出工程选择对话框**（新建工程 / 打开工程 / 最近工程列表）

> 每张蓝图文件是一个 **.bp.json 文件**，可以用文本编辑器打开看结构，也方便备份和版本管理。

---

## 保存蓝图

- **Ctrl+S**：保存当前修改（「工程 ▾ → 保存蓝图」和资源面板右键「💾 保存当前蓝图」也都可用）
- 改文件名的需求：用资源面板的「✏ 重命名…」，别在磁盘上直接改（面板重命名会自动修好组件引用）

建议：
- 做了重要改动后顺手 Ctrl+S（赫萝也会提醒你的~）
- 备份蓝图：直接复制 JSON 文件即可
- 蓝图用到的图片自动存放在工程的 `res/` 子目录（按蓝图所在目录镜像），换电脑只需复制整个工程目录即可

### 工程目录结构

```
工程根/
├── project_meta.json        # 工程元数据（名称 / 时间）
├── <工程名>.bp.json          # 首次建工程时自动生成的蓝图
├── script/组件1/…            # 你自己组织的蓝图目录（怎么放都行）
├── res/                     # 蓝图用到的图片（按蓝图目录镜像，可清理）
│   └── script/组件1/…png
├── templates/               # 旧式模板目录（历史资源，新建不再往这里放）
├── screenshots/             # 热键截图 / 自动抓帧 / 导入图片
├── cache/  debug/           # 运行期缓存与调试输出（可随时清空）
```

## 蓝图文件结构（给好奇宝宝）

实际格式（BlueprintGraph.to_dict）：

```json
{
  "bp_type": "blueprint",
  "nodes": {
    "1": {
      "id": "1",
      "type": "FindImage",
      "x": 100, "y": 200,
      "data": { "temp_target_title": "...", "threshold": 0.85 }
    }
  },
  "links": [
    { "from_node": "id1", "from_port": "out_exec",
      "to_node": "id2", "to_port": "in_exec", "type": "exec" }
  ],
  "breakpoints": [],
  "metadata": { "name": "我的蓝图", "version": "2.0",
                "dev_scale_x": 1.0, "dev_scale_y": 1.0 }
}
```
注意：① nodes 是字典（非数组）；② 节点参数字段叫 `data`（非 `params`）；③ 连线数组叫 `links`（非 `connections`），字段是 `from_node`/`from_port`/`to_node`/`to_port`；④ 无顶层 `variables` 字段（变量存在 SetVariable 节点的 data 里）；⑤ 顶层 `bp_type` 是蓝图类型（`blueprint` = 普通 / `component` = 组件），写在最前面所以资源面板只读文件头就能判类型；老蓝图没有这个字段时，`components/` 目录下的会被当作组件。
