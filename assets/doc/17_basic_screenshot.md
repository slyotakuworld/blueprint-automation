# 📸 截图功能

## 为什么需要截图功能？

蓝图里最常用的就是 **FindImage 找图节点**，而找图需要一张「参考模板图」。截图功能就是让你快速把屏幕上的按钮、图标裁下来，直接存成模板图。

---

## 取素材的两种方式

### 方式一：在属性面板上点按钮

选中 FindImage 节点后，右侧属性面板有：

- **📸 截取目标** 按钮：直接进入截图模式，框选后自动保存并填入路径
- **📂 导入图片** 按钮：选一张已有的图片文件当模板

> 🎯 **框选范围会跟着「临时目标窗口」走**
> 如果该节点已经用「🎯 拾取临时窗口」设过临时目标窗口，点「📸 截取目标」时
> **框选范围会被限定在那个窗口内**：
> - 只能在该窗口内拖框，点到窗口外不会响应
> - 拖到窗口边界会自动贴边，截出来的图一定来自这个窗口
> - 遮罩上会紫色标出该窗口并显示窗口标题
> - 紫色框里的画面是**点按钮瞬间拍下的一张定格画面**（不是实时画面），
>   所以你框到的就是最终存下来的模板内容，二者严格一致；
>   若期间目标窗口自己动了/换了内容，按 ESC 取消重来一次即可
>
> 这样做是为了保证「模板从哪来」和「运行时去哪找」一致 —— 运行时只在该窗口内找图，
> 模板却是从屏幕上别处截的，就必然匹配不上。
> IfImageDetect 的「📷 截图新增一张」、StillnessDetect 的「📍 框选ROI区域」同理。
> 找不到该窗口时会自动回退成全屏框选，并在底部日志里提示。

### 方式二：独立切图工具（批量挑素材时用）

如果一张截图里有**很多**元素要分别取出来当模板（例如整个背包界面、整排技能按钮），
一张张用手框效率太低。这时用独立的切图工具：

> 📁 位置：`G:\work\ui_element_splitter`
> 启动：双击其中的 `run_gui.bat`（工具内自带全局热键截图，默认 `Ctrl+Shift+A`，可在菜单里改）

它能一次把整张图自动切成几十个元素，并让你**挨个挑**，保留想要的再一次性导出：

- 自动检测图中元素边界并切分（多算法合并去重）
- 自动标注元素类型：**按钮 / 文本 / 图标 / 区块**
- 整图上左键=保留、右键=取消；空白处拖拽可手动补框
- 批量全选 / 全不选 / 筛选，再一键导出所有保留的碎图
- 打开图片 / 粘贴剪贴板 / 区域截图 / 全屏截图，也支持游戏内全局热键截图

切好后把导出的 PNG 用上面的 **📂 导入图片** 按钮选进来当模板即可。

> 🐺 这个工具是**通用**的独立程序，不依赖本项目，也能用在任何别的场合。
> 它自带命令行模式（`split_elements.bat` 拖入图片即可），无需打开界面。

## 坐标拾取的基准窗口

Mouse 节点「📍 坐标拾取」在**相对绑定窗口**模式下，基准窗口取自**该节点自己的「临时目标」参数**
（标题子串 / 程序名 / 类名），和运行时解析窗口的口径完全一致；
没配置「临时目标」时就按**绝对屏幕坐标**保存，遮罩上会黄色提示当前处于哪种模式。

> ℹ️ 早期版本还有一个主界面「🎯 截图目标」全局下拉，本版本已**移除**。
> 原因是它和节点参数是两套口径，容易出「按 A 窗口拾坐标、运行时按 B 窗口换算」这种点歪事故。
> 现在编辑器里怎么取，蓝图跑起来就怎么算。

## 截图的小技巧 🐺

### 1. 截多小？

- **能截多小截多小**！框得越紧凑，匹配越快越准
- 比如一个按钮，只框按钮本身就行，不要把周围大片空白也截进去
- 但也别把边切没了，留出 2~3 像素的余量更稳妥

### 2. 截多清晰？

- 画面越清晰、对比度越高，匹配越准
- 有文字的按钮比纯色块好匹配
- 半透明的毛玻璃背景可能难匹配，建议换特征更明显的局部

### 3. 多个状态怎么办？

一个按钮有「未选中」「选中」「高亮」三种颜色：

- 如果三种状态差异大，就用 **灰度匹配**（容忍颜色变化）或 **特征匹配**（抗形变）
- 如果差异特别大，就每个状态截一张，用 **IfImageDetect 多图检测**的「一真即真」模式

### 4. 截图完立刻「测试匹配」

FindImage 节点右侧面板点 **「测试匹配」**：

- 立刻回到目标窗口按实际算法找一遍
- 告诉你用了哪一层（彩色/灰度/特征）、得分多少、坐标对不对
- 不用跑完整蓝图就能验证模板能不能找到，调阈值特别方便 🍎
