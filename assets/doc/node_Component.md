# 🧩 Component · 组件（蓝图复用 / 预制体）

> 把一个蓝图当作「预制体/组件」复用~从下拉列表选一张**组件蓝图**，跑到这里就跳过去跑一遍，跑完再回来继续。支持**显式端口传参**：输入端口喂入参，输出端口收返回值，变量仍然全局共享。

---

## 节点外观

- **分类**：🧠 逻辑
- **配色**：蓝 (#1F6FEB / #58A6FF)
- **短名**：`component`

---

## 端口

| 侧 | 类型 | 名称 | 标签 | 说明 |
|----|------|------|------|------|
| 输入 | ▶ 执行 | `in_exec` | ▶ | 进入组件 |
| 输入 | 数据 | `in_0` … `in_N` | 入参1… | 传给子蓝图 `Start` 入参端口的参数（数量由「输入参数端口数」控制） |
| 输出 | ▶ 执行 | `out_done` | 完成 | 组件跑完后继续往下走 |
| 输出 | 数据 | `out_0` … `out_N` | 返回1… | 接收子蓝图 `End` 返回值端口的返回值（数量由「输出参数端口数」控制） |

---

## 参数一览

| 参数名 | 编辑器 | 默认值 | 说明 |
|--------|--------|--------|------|
| `blueprint_path` | 下拉列表 | `""` | 自动列出**工程里所有「组件蓝图」**（`bp_type = component`），下拉选择即可 |
| `num_inputs` | 整数(0~20) | `0` | 输入参数端口数，与子蓝图 Start 的「入参端口数」一致 |
| `num_outputs` | 整数(0~20) | `0` | 输出参数端口数，与子蓝图 End 的「返回值端口数」一致 |

> 🔧 **端口数会自动对齐**：在下拉里选完组件蓝图后，编辑器会去读那张蓝图里
> `Start` 的「入参端口数」和 `End` 的「返回值端口数」，自动把本节点的 `num_inputs` / `num_outputs`
> 改成一致，并在日志里写明「输入 0→2、输出 0→1」。
> 所以你**不需要**手动对端口数了；万一有人手工改歪，重新选一次组件即可恢复对齐。

## 画布上怎么看出调用了谁

选中组件蓝图后，画布上的 Component 节点会显示一行摘要：**🧩 组件：<组件名>**；
未选择时显示「🧩 未选择组件」。

- **双击画布上的组件节点** = 直接跳转到该组件蓝图去编辑它（跳转前会先问是否保存当前修改）
- 属性面板里也有「↗ 打开这个组件」按钮；节点右键菜单里也有「🧩 打开引用的组件」，效果相同
- 若组件文件被删/改名了，双击会提示并提供「清空引用」选项

### 从资源面板拖蓝图过来（最快）

在左侧「🗂 工程资源」面板里把一张 `.bp.json` **直接拖到画布上**：

- 拖到空白处 → 自动生成一个 Component 节点，并且引用**已经填好**，连下拉都不用点
- 拖到已有的 Component 节点上 → 直接把该节点的引用换成这张蓝图
- 拖进来的若是当前正在编辑的蓝图本身，会被拒绝（会变成自我递归）
- 拖进来的若是「普通蓝图」，日志里会提醒你一声（右键 → 🧩 设为组件蓝图就不会再提示）

## 核心机制

1. **组件 = 一张被标为 `component` 类型的蓝图**，与它放在哪个目录**无关**。
   在资源树里右键任意蓝图 → **🧩 设为组件蓝图**，它就出现在本节点的下拉列表里。
   组件入口是自身的 `Start` 节点，出口是 `End` 节点（或执行流自然走到终点）。
2. **显式传参（带端口）**：本节点的 `in_0/in_1…` 输入值按序传给子蓝图 `Start` 的 `param_0/param_1…` 端口；子蓝图 `End` 的 `ret_0/ret_1…` 端口值按序回到本节点的 `out_0/out_1…` 输出。数量需要两边手动对齐。
3. **变量全局共享（兜底）**：即使不用端口传参，组件蓝图和父蓝图仍共用同一套变量（`ctx.variables`）。组件里 `SetVariable` 存的变量，父蓝图后续节点能直接 `{var}` 读到。
4. **递归可嵌套**：组件里也能再放 Component 节点调用别的组件。
5. **找不到文件 / 加载失败**：视为空操作，打 WARN 日志后走「完成」出口，输出端口统一给 `None`，不中断父流程。
6. **循环引用会被拦住（两处防线）**：
   - **编辑期**：选完组件后会顺着「组件链」往下查，一旦发现绕回当前蓝图（例如 A 调 B、B 又调 A），
     立刻弹窗 + 写 ERROR 日志，并打印完整链路。
   - **运行期**：执行器维护一条「组件调用链」，命中重复（或嵌套超过 32 层）立刻中止该分支并报
     「检测到组件循环引用」，而不是让程序无限递归崩掉。

## 典型用法

### 0. 创建组件的入口（左侧「🗂 工程资源」面板）

- **＋组件** 按钮 / 右键 → 新建组件：在**当前选中的文件夹**里创建一张空白组件蓝图（放哪由你决定）。
- **右键某张蓝图 → 🧩 设为组件蓝图**：把已有蓝图当场转成组件类型，不复制文件、不改名字。
- **资源面板空白处右键 → 🧩 将当前蓝图另存为组件…**：把当前打开的蓝图另存一份（默认落在当前蓝图所在目录）并标记为组件；之后 Ctrl+S 继续保存进组件文件。
- 组件在资源树里显示为橙色的 🧩 `[组件] 名字`，普通蓝图是蓝色的 🗺 `名字`，一眼可辨；双击即可打开编辑。

### 推荐的组织方式

蓝图放哪儿由你决定，**常见做法是按目录分组**：

```
工程根/
├── main.bp.json                # 主流程
├── script/
│   ├── 组件1/
│   │   ├── 登录模块.bp.json      # 🧩 组件蓝图
│   │   └── 签到.bp.json         # 🧩 组件蓝图
│   └── 组件2/
│       └── 支付.bp.json         # 🧩 组件蓝图
└── res/                        # 组件用到的图片（按蓝图目录镜像，可一键清理）
    └── script/组件1/tpl_xxx.png
```

### 1. 把「登录流程」做成组件复用

```
1. 在工程里把「登录流程.bp.json」标为组件蓝图（右键 → 🧩 设为组件蓝图），内容：
     Start(num_params=1) → OpenApp → FindImage(登录按钮, click) → SetVariable(logged_in=true) → End(num_returns=1)

2. 主蓝图拖一个 Component 节点，下拉选择「登录流程.bp.json」。

3. 用端口传参：把上游值连到 Component 的 in_0，子蓝图 Start 的 param_0 就能取到；
   子蓝图 End 的 ret_0 连一个值，主蓝图 Component 的 out_0 就能收到。
```

### 2. 多张蓝图共用一套「每日签到」逻辑

把签到逻辑做成组件蓝图（例如 `script/组件1/签到.bp.json`，标为组件），多张主蓝图各放一个 Component 指向它。改签到逻辑只需改那一张组件蓝图，所有引用处自动生效。

## 常见问题

**Q：组件怎么给父蓝图传参数 / 拿返回值？**
→ 两种方式：① 用端口（推荐）：Component 的 `in_N` 输入 → 子蓝图 Start 的 `param_N`；子蓝图 End 的 `ret_N` → Component 的 `out_N` 输出。② 用变量兜底：组件蓝图里 `SetVariable` 存值，父蓝图后续节点用 `{var}` 插值读取。

**Q：组件必须放在 `components/` 目录里吗？**
→ **不需要**。组件是蓝图自己的类型元数据（JSON 顶层 `bp_type`），放在哪个目录都行。
资源面板里右键蓝图 → 🧩/🗺 随时切换类型。
（老蓝图如果没写过这个字段，`components/` 目录下的会被自动当作组件，兼容旧工程。）

**Q：组件蓝图路径写相对还是绝对？**
→ 现在不用手填路径，直接下拉选择（内部存相对工程根路径，工程目录整体搬走也不失效）。

**Q：组件里含 OCR 节点，导出时会带上 OCR 运行时吗？**
→ 会。导出器会递归检测组件蓝图里的 OCR 节点，只要有就提示携带 `ocr_runtime/`。
