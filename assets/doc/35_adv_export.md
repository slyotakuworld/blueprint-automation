# 📦 导出为独立 EXE

已经调好一张挂机蓝图，不想每次都先打开编辑器再点运行？
**「导出为独立 EXE」** 可以把当前蓝图打包成一个可以单独双击运行的程序，脱离本项目也能跑。

---

## 一、什么时候用它

| 场景 | 说明 |
|------|------|
| 长期挂机 | 双击导出的 exe 直接开始跑，不用开编辑器 |
| 交给别人用 | 对方不需要安装本项目、不需要工程文件，一个 exe 就能跑 |
| 多份蓝图并存 | 每张蓝图导出成一个 exe，互相独立，想跑哪个点哪个 |

> 导出的程序**自带执行引擎**，并且会把蓝图引用到的图片资源一起打包进去，运行时不再依赖原工程目录。

---

## 二、三步导出

1. 在编辑器里**打开**要导出的蓝图（确认蓝图里已经用 BindWindow 节点 / 各节点「临时目标」指定了要操作的窗口）
2. 点工具栏右侧的 **📦 导出 EXE**
3. 在弹出的对话框里确认资源清单 → 选择导出路径（默认在桌面、文件名为蓝图名）→ 点 **开始导出**

导出完成后可以直接点「打开所在文件夹」去看产物。

对话框里会列出：

- **✔ 会被打包的图片**：数量与各自体积
- **✘ 找不到的图片**：这类引用不会被包含，运行时对应节点会失败，导出前最好先处理掉

### 🩺 导出前体检（自动）

点开导出对话框时，会先自动做一次体检，把「导出去也跑不起来」的坑提前拦下来：

| 体检项 | 级别 | 说明 |
|--------|------|------|
| 组件引用断链 | ⛔ 错误 | 蓝图里「调用组件」指向的 `.bp.json` 不存在（含子画布 / 递归嵌套里的组件）。会列出是哪几个，导出前先修好 |
| OCR 运行时缺失 | ⚠ 警告 | 蓝图里有「文字识别」节点，但找不到 `ocr_runtime/` 目录 → 导出后必须把该目录放到 EXE 同级 |
| 运行时模板过期 | ⚠ 警告 | `BlueprintRuntime.exe` 比编辑器里的运行时代码旧 → 导出的 EXE 跑的还是旧代码，先执行一次 `start.cmd build-runtime` 再导出 |

出现 ⛔ 级问题时，点「开始导出」会再确认一次（可以强制导出，但那些节点运行时必然失败）。

---

## 三、导出的程序长什么样

双击导出的 exe，会弹出控制面板。**默认不会自动开跑**，由你点「▶ 开始」或按 F5 启动。
（想双击就跑，勾选面板上的「启动后自动运行」——这个勾选会记住，下次开还是它。）

| 元素 | 作用 |
|------|------|
| 状态栏 | 显示当前执行到第几步、哪个节点 |
| 日志区 | 实时输出每个节点的执行日志 |
| ▶ 开始 | 从 Start 开始跑；跑完后这个按钮可以再点，等于再跑一遍 |
| ⏸ 暂停 / ▶ 继续 | 冻结当前步骤，不丢运行状态；再点一次继续 |
| ⏹ 停止 | 优雅停止（跑完当前节点后退出） |
| 🔄 重新开始 | 不管当前跑到第几步，先停掉再从 Start 重跑一遍 |
| ☐ 启动后自动运行 | 勾上 = 双击 exe 直接开跑（挂机用）；设置会记住 |
| 最小化到托盘 | 收进系统托盘，蓝图继续在后台跑 |

**全局热键**（控制面板不在前台也生效；与编辑器默认快捷键保持一致，不用重新学）：

| 热键 | 作用 |
|------|------|
| **F5** | 开始 / 重新开始 |
| **F6** | 暂停 / 继续 |
| **F7** | 停止（当前节点跑完就停） |
| **F12** | 紧急退出（鼠标乱飞时救命用，直接结束进程） |

## 四、几点说明

### 1. 图片资源会自动带走

找图 / 多图检测这类节点记的是图片的**绝对路径**。导出时会自动把这些图片复制进 exe，
运行时再还原成解包目录里的路径，所以：

- 原工程目录删掉 / 改名，导出的 exe **照样能跑**
- 但**导出之后**再改模板图，导出的 exe 不会跟着变——想更新就重新导出一次

### 2. 运行产生的文件放在哪

导出的程序运行时，会把自带资源解包到：

```
%LOCALAPPDATA%\BlueprintRuntime\<指纹>\
```

debug 日志、截图缓存等也在这个目录下，不会污染 exe 所在位置。

控制面板上的「启动后自动运行」勾选也存在这里（`runtime_prefs.json`），
所以同一个导出的 exe，下次打开会记得你上次的选择。

### 3. 绑定窗口怎么办

蓝图里用 **OpenApp / BindWindow** 节点写好的窗口绑定逻辑会照常执行。
如果蓝图完全没绑窗口，就是全屏模式。

> ℹ️ 导出的独立 EXE 与编辑器遵循**同一条规则**：目标窗口 100% 来自蓝图自身
> （BindWindow 节点 / 各节点「临时目标」）。
> 本版本已从主界面移除「🎯 截图目标」下拉，所以「编辑器内点▶运行」与「导出的 EXE」
> 行为完全对齐：在编辑器里跑之前，请确保蓝图自己已经把窗口绑好了。

### 4. 体积

因为是自带 Python 运行环境的单文件程序，exe 体积通常是几十 MB 起步，属于正常现象。

### 5. 找不到运行时模板？

「导出 EXE」依赖一个预先构建好的运行时模板 `BlueprintRuntime.exe`：

- **正式发布版**：已随主程序一起分发，开箱即用
- **源码运行版**：先在项目根目录执行 `start.cmd build-runtime`（或双击 start.cmd 选「4. 仅重打运行时模板」）生成模板

如果对话框底部提示"运行时模板缺失"，按上面的提示补一次即可。
