# 🔵 End · 结束

> 和Start配对的终点~跑到咱这里就算这条分支收工啦，不会再继续往下走咯。

---

## 节点外观

- **分类**：🧠 逻辑
- **配色**：蓝 (#0b3d91 / #1565c0)
- **短名**：`end`

---

## 端口

| 侧 | 类型 | 名称 | 标签 | 说明 |
|----|------|------|------|------|
| 输入 | ▶ 执行 | `in_exec` | ▶ | 上游跑到这里，该分支就结束 |
| 输入 | 数据 | `ret_0` … `ret_N` | 返回1… | 本蓝图作为「组件」被调用时的返回值端口（数量由「返回值端口数」控制，普通蓝图保持 0） |
| 输出 | - | - | - | 无输出端口（终点嘛~） |

---

## 参数

| 参数名 | 编辑器 | 默认值 | 说明 |
|--------|--------|--------|------|
| `num_returns` | 整数(0~20) | `0` | 返回值端口数。本蓝图作为「组件」被调用时，连到 `ret_0/ret_1…` 端口的值会按序交还给调用方「组件」节点的输出端口 |

---

## 用法说明

### 1. 标记一条分支的终点
```
Start → OpenApp(成功) → Mouse → PressKey → [End]
                  ↓
                (失败) → Notify("打不开程序！") → [End]
```
每条逻辑链路都推荐以 End 结尾，读图一眼能看清楚分支到哪结束。

### 2. 不是强制的，但建议用
不接 End 也没关系：最后一个节点执行完没有下游，这条链路也会自然停下。
但接了 End 更好：
- 状态面板一眼看到哪条分支"跑到终点"了
- 以后加节点不会不小心连错位置

## 常见问题

**Q：一张蓝图可以有多个 End 吗？**
→ 可以！而且**非常推荐**。每条分支（成功/失败、yes/no）各接一个 End，蓝图结构更清晰。

**Q：跑到 End 之后蓝图就停止了吗？**
→ 只是这条**执行分支**结束。如果蓝图里还有 Loop 循环、Sequence 其他分支在跑，它们继续。整个蓝图真正停止的条件是：所有正在执行的分支都结束（或者用户点了停止按钮）。
