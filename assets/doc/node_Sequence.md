# 🔀 Sequence · 顺序执行（纯串行队列）

> 把要顺序执行的一串动作塞进子画布里，从上到下一条条跑，**不做任何条件判断**。双击本节点进入子画布编辑，跑完就继续往下走。
> **不需要接「结束」节点** —— 跑到最后一个节点就是收尾；只有节点执行报错（异常 / 死循环）才走「失败」出口。
> 想中途提前收工？在子画布里放一个「**退出串行**」节点（默认走「完成」，勾上「标记为失败」则走「失败」）。
> 想要"哪个成功走哪个 / 失败重试"那种逻辑，请用「条件判断」节点自己编排。

## 节点外观

- **分类**：🧠 逻辑
- **配色**：蓝灰 (#57606A / #58A6FF)
- **短名**：`seq`

---

## 端口

| 侧 | 类型 | 名称 | 标签 | 说明 |
|----|------|------|------|------|
| 输入 | ▶ 执行 | `in_exec` | ▶ | 上游触发 |
| 输出 | ▶ 执行 | `out_done` | 完成 | 顺序体正常跑完（一路跑到末尾 / 走到「结束」节点），或走了未勾「标记为失败」的「退出串行」 |
| 输出 | ▶ 执行 | `err` | 失败 | 顺序体里有节点**执行报错**（抛异常、死循环），或「退出串行」勾了「标记为失败」 |

## 子画布专用节点

进入顺序体子画布后，节点库会**额外**给出一个只能在这里用的节点（回根图就看不到）：

| 节点 | 短名 | 作用 | 参数 |
|------|------|------|------|
| **退出串行** | `exit_seq` | 跑到它就**立即结束整个顺序执行**，后面的节点不再执行 | `as_failure`（标记为失败，默认关） |

**`as_failure`**：不勾（默认）→ 走「**完成**」出口；勾上 → 走「**失败**」出口。

---

## 核心机制

1. **子画布容器**：顺序执行的内容不是靠"拉线"表达，而是塞在本节点的子画布里。双击节点即可进入子画布，像编辑一张独立蓝图一样编辑顺序动作。
2. **纯串行**：子画布里从 `Start` 开始，一条执行流顺序跑到底，中间不做短路 / 完全求值 / 一真即真之类的判定。
3. **只有「异常报错」才算失败**：判定「跑完了没有」只看**有没有节点执行出错**
   （抛异常 / 死循环）；另外，「退出串行」勾了「标记为失败」也算失败。
   跑到最后一个节点、末尾出口悬空、**没有接「结束」节点** —— 统统算「完成」。
   也**不看中途经过了哪些端口** —— 某个节点走了 `not_found` / `no` / `err` 这类端口并不代表失败
   （那是它自己的正常分支）。
   > 三个容器（循环 / 顺序 / 并行）这条口径**完全一致**。曾经短暂要求过「必须走到结束节点」，已还原。
   >
   > 💡 新建的顺序体只自动放好一个 `开始` 节点，往下接你的动作就行。「结束」节点仍然可以放
   > （表示"这段到此为止"，只是给人和调试看的），但**不是必须的**。
4. **点「← 返回父图」退出**：编辑完点面包屑上的返回按钮，**改过**的内容会回写进本节点。
   > 💡 双击进去只是「看」，不算修改：没动过任何东西（加/删节点、改参数、连线）时，进出子画布不会让蓝图变成「有未保存修改」。

## 典型用法

### 把一组固定的串行动作打包

```
主蓝图：Start → Sequence(双击进入) → 后续节点

进入 Sequence 子画布：
    Start → 打开背包 → 等待0.5s → 点击使用道具 → 等待1s → 关闭背包 → End

返回父图后，主蓝图里这段「开背包用道具」就是一个黑盒，跑完继续往下。
```

→ 适合把"连续点击、输入、等待"这类没有分支的固定流程收拢成一个块，让主蓝图更清爽。

### 中途提前收工 / 按失败处理

```
进入 Sequence 子画布：
    Start → 检查背包 → 退出串行
                     ↓
              后面的「使用道具」不执行了，直接回到主蓝图
```

→ 「退出串行」默认走「完成」；如果这一步失败就该让主流程走失败分支，
把它的「**标记为失败**」勾上即可（此时本节点走 `err`）。

## 常见问题

**Q：想按条件分支 / 失败重试怎么办？**
→ Sequence 是纯串行，不做判断。需要分支请用「条件判断(VarSwitch)」节点 + 连线编排；需要循环请用「循环(Loop)」节点；需要多条同时跑请用「并行执行(Parallel)」节点。

**Q：什么情况下会走「失败」出口？**
→ 两种情况：① 子画布里有节点**执行报错**（抛异常、死循环）；② 「退出串行」节点勾了「标记为失败」。
流程停在最后一个节点、某个端口没连下游、或者压根没放「结束」节点 —— **都不会判失败**。

**Q：「退出串行」和「结束」节点有什么区别？**
→ 「**结束**」只是"这条执行流到这里为止"，它**不会**改变本节点走哪个出口，也不能跳过后续节点之外的东西
（顺序体本来就是一条线）。「**退出串行**」是**主动提前结束整个顺序执行**，还能通过 `as_failure`
直接决定本节点走「完成」还是「失败」——想在顺序体里做「这一步不行就整体判失败」，用它。

**Q：顺序体里放「跳出循环(Break)」会怎样？**
→ （这是老蓝图的残留写法，现在节点库里给的是「退出串行」）不会报错、也不会判失败：
顺序体是"一条线"，没有「轮次」可跳，所以按**正常结束**处理，走「完成」出口，
同时在运行日志里打一条 WARN 提醒你该用「退出串行」或「再次循环」这类节点。

**Q：和「循环(Loop)」有什么区别？**
→ 循环是"同一段内容跑 N 次"，顺序执行是"一串内容跑 1 次"。两者都用子画布容器承载内容，
交互一致（双击进入、返回回写），**「完成 / 失败」的判定口径也完全一样**：
不要求接「结束」节点，只有节点执行报错（或退出节点标记为失败）才算失败。
