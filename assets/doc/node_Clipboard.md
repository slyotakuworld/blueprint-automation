# 📋 Clipboard · 剪贴板

> 管系统剪贴板的小助手~要么读出来存变量还顺带给下游数据线；要么把汝写的（或上游传进来的）内容写进去；也能一键清空剪贴板哟。

---

## 节点外观

- **分类**：🎯 动作
- **配色**：深紫 (#4527a0 / #7e57c2)
- **短名**：`clipboard`

---

## 端口

### 输入
| 名称 | 类型 | 标签 | 说明 |
|------|------|------|------|
| `in_exec` | ▶ 执行 | ▶ | 上游触发 |
| `in_text` | ○ 数据(str) | 写入内容(连线优先) | **三种模式下都固定存在**（切模式不会消失、不会断线）。此端口有连线且值非空 → 优先用连线值；空则用参数 `value`。**只有 write 模式会读它**，read / clear 模式下连了也不会写——但线会保留，切回 write 立即可用 |

### 输出
| 名称 | 类型 | 标签 | 说明 |
|------|------|------|------|
| `out_done` | ▶ 执行 | 完成 | 操作成功（读/写/清空都算）→ 走这里 |
| `err` | ▶ 执行 | 失败 | 硬失败才走这里：缺 `pywin32` 依赖、内存里的 mode 取值非法、或读写过程抛异常。**写/清空被别的程序抢占用导致失败时不会走 err**（会各重试 2 次 + 读回校验，失败只打一条 WARN 日志，仍走「完成」） |
| `out_text` | ○ 数据 | 剪贴板文本 | read = 读到的文本；write = 刚写入的文本；clear = 空字符串 |

---

## 参数一览

| 参数名 | 编辑器 | 默认值 | 必填 | 说明 |
|--------|--------|--------|------|------|
| `mode` | 下拉 | `read` | - | 模式：`read`（读取）、`write`（写入）、`clear`（清空） |
| `value` | 多行文本 | `""` | - | 仅 write 模式生效：手写要写进剪贴板的文本，支持 `{var}` / `${var}` / `{= 表达式 }` 插值。与左侧「写入内容」端口二选一，**端口连线非空时优先** |
| `output_var_name` | 文本 | `clip_text` | - | 仅 read 模式生效：读到的文本**同时存为全局变量** `clip_text`，下游节点可直接 `{clip_text}` 引用 |

## 实现原理

整条链路只做一件事：**读写 Windows 系统剪贴板**（就是 Ctrl+C / Ctrl+V 用的那个）。

- **后端**：直接调用 Windows 原生剪贴板 API（`pywin32` 的 `win32clipboard`），
  没有走 Qt 或第三方剪贴板库，所以对任何程序（记事本、浏览器、游戏）复制的文本都通用。
- **只处理文本**：固定用 Unicode 文本格式（`CF_UNICODETEXT`）。剪贴板里是图片 / 文件 / HTML
  时，按文本读会得到空字符串（不会报错，也不会转换）。
- **先开再关**：每次读写都是 `OpenClipboard → 操作 → CloseClipboard` 三段式，且失败会**重试 2 次**
  —— 剪贴板是全局独占资源，别的程序（尤其是同步/云盘类软件）正好占用时会开不开，重试能救回大部分情况。
- **写/清空后会读回校验**：写完立刻读一遍比对，不一致就写一条 WARN 日志（写成功但内容被别的程序
  抢改的情况很罕见，留个痕迹便于排查）。
- **线程安全**：剪贴板 API 属 COM 组件，节点在每次执行时都会在当前线程做配对的
  `CoInitialize / CoUninitialize`，所以蓝图在后台线程跑也不会出 "CoInitialize has not been called"。
- **并行安全**：剪贴板是**系统级单例**，同一时刻只能有一个写入方。所以本节点的「读 / 写 + 读回校验 /
  清空 + 读回校验」整段、以及按键节点粘贴模式的「写 + Ctrl+V」，共用同一把**全局剪贴板锁**。
  → 放进并行分支时，这些操作会**串行排队**，不会互相覆盖、也不会读到别人写了一半的内容；
  代价是这几步不再真并发（本来就只是毫秒级），且**谁先谁后不保证**。

## 三种模式详解

### 模式 1：read（读取剪贴板）
```
mode = read
output_var_name = clip_text
```
运行时：
- 把当前系统剪贴板里的文本读出来
- 两条路同时给下游：
  1. 绿色数据端口 `out_text` → 可以直接连到下一个节点（比如 SetVariable.in_0）
  2. 自动存成变量 `clip_text` → 下游所有文本参数 `{clip_text}` 都能用

### 模式 2：write（写入剪贴板）
```
mode = write
value = 赫萝给汝准备好的一段文本：{hello_msg}
```
运行时：
- 如果左侧 `写入内容(连线优先)` 端口连了上游，且上游值非空 → 优先写上游的值
- 否则写参数里的 `value`（支持变量插值）

> 💡 **写入内容有两个入口，不是重复设计**：
> 左侧端口是给**上游节点**传值用的（例如 `Command.stdout` → 剪贴板），
> 下方参数是给**手写常量**用的。两者同一时刻只用得上一个，**端口有值优先**。
> 参数支持 `{var} / ${var} / {= 表达式 }` 插值；端口值**不插值**（上游给什么就写什么，它已经是最终值）。
> 这个端口**固定存在** —— 切换操作模式它不会消失，连着的线也不会断；
> 只是 read / clear 模式下执行器不会去读它（连了也不写）。

### 模式 3：clear（清空剪贴板）
```
mode = clear
```
→ 把系统剪贴板内容清空，常用于登录密码等敏感信息场景。

## 典型用法

### 1. 读剪贴板 → 存变量 → 条件判断
```
连线：
  Start → Clipboard(read) → VarSwitch

Clipboard：
  mode = read
  output_var_name = clip_text

VarSwitch cases：
  {clip_text} == "已授权"
```
→ 如果剪贴板里正好是"已授权"三个字，就走 yes 分支。

### 2. 把命令输出写进剪贴板
```
连线：
  Command.stdout → Clipboard.in_text
  Command.out_done → Clipboard.in_exec

Clipboard：
  mode = write
  value = （这个参数没用，因为连线值优先）
```
→ Command 执行完，把输出直接写进剪贴板，用户可以 Ctrl+V 粘贴。

### 3. 生成一段提示并复制
```
SetVariable：
  order_id = 202607080001
  total = 288.00

→ Clipboard(write)
  value = 【订单通知】订单号{order_id}，合计{total}元，谢谢惠顾~
```
→ 点一下按钮，复制一段格式化好的文本。

## 常见问题

**Q：「写入内容」支持变量吗？怎么用？**
→ 参数支持。写法 `{变量名}`，例如 `订单号 {order_id}`；也支持 `${变量名}` 和 `{= 表达式 }`。运行时先算出真实文本，再写进剪贴板。
→ 从左侧「写入内容」端口连线传进来的值**不做插值**——上游给什么就写什么。

**Q：「写入内容」端口在读取 / 清空模式下为什么没反应？**
→ 端口**一直都在**（切模式不会消失、不会断线），但它只在「操作模式 = 写入」时被读取。读取 / 清空模式下连了也不会写，切回「写入」立刻生效。

**Q：剪贴板里有图片，读出来是啥？**
→ 目前 Clipboard 节点**只处理文本**。图片/文件路径格式的剪贴板内容会被忽略（out_text 是空字符串）。

**Q：写中文乱码？**
→ 不会，内部统一用 Unicode，Windows 剪贴板原生支持中文。
