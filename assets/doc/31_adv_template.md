# ⚡ 找图匹配算法详解

FindImage 和 IfImageDetect 两个节点都有 `match_strategy`（匹配算法）参数。这一节把四种算法的原理、优缺点、调参建议讲透。

---

## 四种算法速查表

| 算法 | 中文名 | 原理 | 抗变化能力 | 速度 | 推荐场景 |
|------|--------|------|-----------|------|----------|
| `template` | 彩色模板匹配 | 把彩色模板图（BGR三通道）归一化互相关（NCC）多尺度扫描 | 低（颜色、尺寸、旋转一变就找不到） | ⚡⚡⚡ 最快 | UI按钮、图标（尺寸固定、颜色稳定） |
| `gray` | 灰度模板匹配 | 转单通道灰度后做 NCC | 中（容忍颜色变化，只看亮度形状） | ⚡⚡ 快 | 有选中/未选中态的按钮、文字图标 |
| `feature` | AKAZE 特征匹配 | 提取局部角点/边缘特征点 → 特征描述子匹配 → RANSAC 几何验证 | 高（抗颜色/光照/轻微旋转缩放/局部遮挡） | ⚡ 稍慢 | 复杂画面、变形、光照不稳定 |
| `hybrid` **默认** | 智能混合级联 | 彩色→灰度→AKAZE，三层依次尝试，任何一层中就算成功 | 最高（兜底强） | 中（最差情况才跑三层） | 大多数场景首选 |

---

## 彩色模板匹配（template）

### 原理
1. 把屏幕截图和模板都当成 RGB 三通道图像
2. 用归一化互相关（NCC = Normalized Cross-Correlation）在屏幕上滑窗：
   ```
   得分 = 相关性（越接近 1.0，两张小图越像）
   ```
3. Fast Mode：对模板在 0.8 ~ 1.2 范围内做 30 个不同缩放比例，依次尝试（保证常见 0.8/0.9/1.0/1.1/1.2 都能覆盖到）
4. 每个尺度都算一遍，取所有尺度里最高分的那个位置返回
5. 即使阈值中途命中了，也继续跑完所有尺度 → **最终返回全局最佳得分**（而不是第一个过阈值的）

### 阈值参考
| 场景 | threshold 推荐 |
|------|---------------|
| 完全精确的 UI 按钮（不会变） | 0.93 ~ 0.97 |
| 有轻微渲染差异（同分辨率） | 0.90 ~ 0.93 |
| DPI 缩放可能变化 | 0.88 ~ 0.92 |

### 优点
- 最精确、最快
- 纯色块、简单图标几乎 0 误判

### 缺点
- 按钮颜色变了（灰掉/高亮态）→ 相关性暴跌
- 大小变了超过 ±20% → 找不到（Fast Mode 最多 ±20%）
- 旋转了一点点 → 找不到

## 灰度模板匹配（gray）

### 原理
跟彩色一模一样，只是把 RGB 转成单通道灰度再做 NCC：
```
gray = 0.299 × R + 0.587 × G + 0.114 × B
```

这样就**扔掉了颜色信息**，只保留亮度形状 → 按钮从蓝变黄也没关系，只要黑的笔画位置一样就认得出。

### 典型场景
- 同一个按钮有「正常 / 悬停 / 选中 / 灰掉」四种颜色状态，你不想每个状态都截一张图
- 游戏 UI 皮肤切换，但布局不变
- 文字按钮（底色变化不影响文字笔画形状）

### 阈值参考
比彩色要低一些，因为少了颜色通道，区分度下降：
| 场景 | threshold 推荐 |
|------|---------------|
| 纯文字按钮（字体清晰） | 0.88 ~ 0.92 |
| 颜色变化但形状固定图标 | 0.85 ~ 0.90 |

## AKAZE 特征匹配（feature）

### 原理
1. 在屏幕截图和模板上各跑一遍 AKAZE 算法，提取**局部特征点**：
   - 特征点 = 角点、边缘端点、T 字路口等"独特"的像素点
   - 每个点附带一个**特征描述子**（61 维向量，描述周围像素长啥样）
2. 用 KNN 匹配两边的描述子，找"长得最像"的配对
3. 取 Lowe's ratio test 保留**高质量配对**（好匹配 / 次好匹配 < 0.7）
4. 用 RANSAC（随机抽样一致）算法**几何验证**：
   - 随机挑 4 对配对计算仿射变换矩阵
   - 看其他配对有多少个能被这个矩阵"解释"（内点 inlier）
   - 内点数 ≥ **固定最少 4 个**才算整体匹配成功
   - （不再有 50% 内点比例阈值，内点绝对数 ≥ 4 就过）
5. 用变换矩阵把模板 4 个角投影到屏幕上 → 取 min/max 坐标得到外接矩形 → 就是检测到的位置
6. **得分公式**（和 Qflow 一致）：
   ```
   score = min(1.0, len(good_matches) / 4 × 0.5 + 0.5)
   ```
   有 4 对好配对 = 0.75；8 对及以上 = 1.0

### 阈值传给 AKAZE 的处理
- 节点参数里用户填的 `threshold`（默认 0.9）**直接作为 AKAZE 的基准**
- 特征路径会先经过 `get_calibrated_gray_threshold` 加 gray_threshold_offset，再**下调 0.1**
- 最终夹在 **[0.55, 0.97]** 之间（防止太小误判、太大太严）
- AKAZE 的 threshold 本身做 **[0.01, 1.0] 边界 clamping**，不会跑出范围

### 典型场景
- 轻微旋转了的图标（游戏里歪了一点点的道具）
- 有局部遮挡的场景（一半被弹窗挡住了）
- 画面整体光照忽明忽暗（白天/黄昏游戏场景）
- DPI 缩放比例不确定的用户电脑

### 为什么纯色图会失败？
→ 纯色图没有"独特的局部点"，AKAZE 找不到特征点 → 根本没配对 → 0 个好配对 → score < 阈值。
这种图请用 template 或 gray，别用 feature。

## 智能混合（hybrid）三级联

```
第 1 层：彩色模板多尺度（30 个尺度）
  ✅ 过阈值 → 立刻返回（记录路径：彩色）
  ❌ 没过 → 进入第 2 层

第 2 层：灰度模板多尺度（30 个尺度）
  ✅ 过阈值 → 返回（记录路径：彩色→灰度）
  ❌ 没过 → 进入第 3 层

第 3 层：AKAZE 特征匹配
  ✅ ≥ 4 内点 + 阈值过 → 返回（路径：彩色→灰度→AKAZE）
  ❌ → 返回 未找到
```

### 为什么推荐大多数场景用 hybrid？
兼顾了：
- 速度（90% 的情况在第 1 层彩色就找到了，只花 ~10ms）
- 兜底（按钮变色→第 2 层灰度；形状变形→第 3 层特征）
- 可追踪性（测试匹配按钮告诉你路径是 "彩色→灰度→AKAZE"，你就知道模板是不是该重截一张更清晰的了）

## 调参最佳实践 🍎

### 场景 1：怎么都找不到
1. **先点「测试匹配」按钮**（必做！别瞎跑蓝图）
2. 看日志/结果里写的是哪层失败：
   - "彩色得分 0.73 < 阈值 0.9" → 降低 threshold 到 0.85 试试，或者换 hybrid
   - "彩色失败→灰度也失败→AKAZE 只有 2 内点 < 4" → 模板太糊/太纯色，重截一张特征更丰富的
3. 窗口是不是最小化了？是不是被别的窗挡住了？search_mode 是 relative 但目标程序没绑对？

### 场景 2：总是误判（不是目标却被当成目标）
1. threshold 调高到 0.93+
2. 开 **use_feature_assist = verify 验证模式**：模板匹配成功后再用特征辅助交叉验证，双保险
3. 模板图截得更紧凑一点（别把大片相似的背景区域包进去）

### 场景 3：有多种状态的按钮
- 颜色会变 → 用 gray 或 hybrid
- 旋转/形变 → 用 feature 或 hybrid
- 想保险 → hybrid，阈值别设太低 0.9 左右即可
