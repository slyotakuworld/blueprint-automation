# 📸 Screenshot · 截图

> 把目标窗口（或屏幕）的某个 ROI 区域截下来，输出成图像给下游用~可以直接喂给网络请求节点，把图交给别的程序处理，也能存成文件。

---

## 节点外观

- **分类**：👁 感知
- **配色**：深青蓝 (#0e3a5c / #1f8dd6)
- **短名**：`screenshot`

---

## 端口

### 输入
| 名称 | 类型 | 标签 | 说明 |
|------|------|------|------|
| `in_exec` | ▶ 执行 | ▶ | 上游触发 |

### 输出
| 名称 | 类型 | 标签 | 说明 |
|------|------|------|------|
| `out_done` | ▶ 执行 | 完成 | 截图成功 |
| `err` | ▶ 执行 | 失败 | 截图失败 / ROI 为空 / 没找到目标窗口（window 模式） |
| `image_bgr` | ○ 数据 | 图像(BGR) | numpy 数组（运行时内存对象）。目前**没有内置节点接收图像入参**，主要供二次开发/扩展节点使用；要落盘或外传请用 `image_png_bytes` / 「保存路径」 |
| `image_png_bytes` | ○ 数据 | PNG字节 | PNG 编码后的字节流，可作网络请求的 body |
| `image_path` | ○ 数据 | 保存路径 | 若填了「保存路径」，这里是落盘后的文件路径，否则空字符串 |

---

## 参数一览

| 参数名 | 编辑器 | 默认值 | 说明 |
|--------|--------|--------|------|
| `range_mode` | 下拉 | `window` | 截取范围：`window`=目标窗口 / `fullscreen`=全屏。选 `window` 就必须真的截到目标窗口，**找不到直接走「失败」，不会降级成全屏** |
| `target_title` | 文本 | `""` | 窗口标题子串（仅 window 模式）；支持 `{var}` |
| `target_exe` | 文本 | `""` | 程序名子串（如 notepad.exe，仅 window 模式）；支持 `{var}` |
| `target_class` | 文本 | `""` | 窗口类名精确匹配（仅 window 模式）；支持 `{var}` |
| `roi` | 四元组 | `(0,0,0,0)` | 相对窗口/屏幕左上角的 (x, y, w, h)；全 0 = 截整个范围。可点工具栏「🖱 框选ROI」鼠标框选 |
| `roi_preview_b64` | 文本 | `""` | ROI 缩略图（自动记录不用手填） |
| `save_path` | 文本 | `""` | 留空=只输出不落盘；填了就存 PNG 并输出 image_path；支持 `{var}` |

> 📌 **参数按范围自动显隐**：选「截取范围=**全屏**」时，面板**不会显示**「目标窗口·标题/程序名/类名」这几个参数——全屏截图用不到它们，省得误填还以为生效了。切回「目标窗口」才会出现。

> 💡 **工具栏快捷操作**（选中截图节点时出现在属性面板上方）：
> - 🖱 **框选ROI**：鼠标拖框选一块区域，自动回填 `roi` 并显示预览图。
> - 🎯 **拾取目标窗口** / 📋 **从列表选择**（仅「目标窗口」模式）：点窗口或从列表选，自动回填 `target_title/exe/class`。
>   **从列表选择会把最小化的窗口也列出来**（排在最后、状态列标「最小化」）；拾取要靠鼠标点，最小化的窗口点不到所以不列。

## 典型用法

### 1. 截目标窗口某个区域，发给别的程序处理
```
Screenshot(截取范围=目标窗口, 目标窗口·程序名=game.exe, ROI=(100,50,200,80))
   └─ image_png_bytes ─→ HttpRequest(POST body=图片字节)
```
拿到 `image_png_bytes` 后接网络请求节点，把图发给后端识别/处理。

### 2. 截一小块存文件
```
range_mode       = window
target_title     = 我的窗口
roi              = (10, 10, 120, 40)
save_path        = C:\temp\snip.png
```
→ 截下目标窗口左上角 120×40 那块，存成 PNG，`image_path` 输出路径。

### 3. 直接截全屏（不需要目标窗口）
```
range_mode = fullscreen
roi        = (0, 0, 0, 0)     ← 全 0 = 整块桌面
```
→ 面板上不会显示目标窗口参数，因为全屏模式用不上。

### 4. 截图节点和文字节点的分工
文字节点**自己按「识别范围 + ROI」现场截图识别，不接收外部图像**，
所以「先截图 → 再喂给文字节点」这种串联是多余的：直接给文字节点设好范围/ROI 就行。

截图节点留给「要把画面存成文件 / 发给外部接口」的场景：用 `image_png_bytes`（PNG 字节流）
或填「保存路径」落盘，再配合网络请求等节点使用。

## 常见问题

**Q：window 模式没找到窗口会怎样？**
→ **直接走 `err`（失败）出口，不会退化为全屏截图。**
退化成全屏会让下游把「整屏」当「窗口画面」用，属于静默做错事，事后很难查。
失败日志会区分两种情况：
- 定位条件一个都没填 → 提示补上「标题 / 程序名 / 类名」，或把截取范围改成「全屏」；
- 填了但没匹配到窗口 → 提示目标窗口可能还没打开，或定位条件需要修正。

另外两种情况也走 `err`：窗口矩形算出来无效（窗口完全在屏幕外或被隐藏）；ROI 裁剪结果为空。

> 💡 有一种「回退」是保留的：目标窗口在、但后台截窗方式拿不到画面时，会改用「前置窗口 → 截全屏 → 按窗口矩形裁剪」。
> 这属于**同一个目标窗口的取图方式回退**（截到的仍是目标窗口），不影响上面「找不到窗口就失败」的严格语义。

**Q：全屏模式下还能填目标窗口参数吗？**
→ 参数还在（不会被清空，方便来回切换），但面板会**隐藏**它们、运行时也不读取。要用目标窗口就切回「目标窗口」模式。

**Q：image_bgr 能存变量吗？**
→ 不能。它是运行时内存对象（numpy 数组），变量只存字符串/数字。要留证据或传给外部，
请用 `image_png_bytes`（PNG 字节流）或填「保存路径」落盘后再用路径。
