# 赫萝蓝图自动化

**可视化节点式桌面自动化工具 —— 拖拽连线，把重复劳动交给赫萝 🍎**

许可证 **GPL-3.0** ｜ 平台 **Windows 10 / 11** ｜ Python **3.10+** ｜ Node.js **18+**（仅启动器需要）

## 📖 这是什么

赫萝蓝图自动化是一款运行在 Windows 上的**可视化节点式自动化工具**。把「启动程序 → 找图点击 → 输入文字 → 等待」这些积木块拖到画布上、连上线，就能拼出一条完整的自动化流程，全程不需要写一行代码。

它的核心是**蓝图（Blueprint）**：一张保存为 `.bp.json` 的流程图，既能放进编辑器里反复调试，也能**一键打包成独立的 EXE**，脱离本项目单独运行。

> 🎮 适合游戏日常挂机、办公批量操作、UI 自动化测试，以及任何"每天都要重复点一遍"的场景。

## 🧠 节点一览

节点库分四大类，常驻节点共 23 个：

| 分类 | 节点 |
|------|------|
| 🚀 **应用控制** | 启动程序、激活窗口、打开网页、执行命令、网络请求 |
| 🧠 **逻辑** | 开始、结束、组件、循环、顺序执行、并行执行、设置变量、条件判断 |
| 🎯 **动作** | 鼠标、按键、等待、通知、剪贴板 |
| 👁 **感知** | 找图、多图检测、截图、静止、文字（OCR） |

另有 5 个子画布专用节点，**只在进入对应子画布后**才出现在左侧节点库：

| 所在子画布 | 出现的节点 |
|------------|-----------|
| 循环体（双击「循环」节点进入） | 再次循环、跳出循环 |
| 顺序体（双击「顺序执行」节点进入） | 退出串行 |
| 并行体（双击「并行执行」节点进入） | 分支入口、退出并行 |

> 📚 每个节点的参数含义、端口方向、取值范围，都写在内置手册里（编辑器工具栏最右侧的「文档攻略」按钮）。

## 🚀 快速开始

### 环境要求

| 依赖 | 版本 | 说明 |
|------|------|------|
| **Windows** | 10 / 11 | 仅支持 Windows，依赖 `pywin32` / `win32gui` 等系统接口 |
| **Python** | 3.10+ | 编辑器与运行时本体 |
| **Node.js** | 18+ | **仅用于一键启动器** `start.cmd`；不想装 Node 也可以直接跑 Python |

### 一键启动（推荐）

1. 安装 [Python 3.10+](https://www.python.org/downloads/)（安装时务必勾选 **Add Python to PATH**）
2. 安装 [Node.js 18+](https://nodejs.org/)
3. **双击项目根目录的 `start.cmd`**，在弹出的中文菜单里选：

```
1. 启动编辑器（开发模式，自动检查依赖与 OCR 模型）
2. 仅检查 / 安装环境依赖与 OCR 模型（不启动）
3. 打包发布版（编辑器 + 运行时模板 → dist\BlueprintAutomation）
4. 仅重打运行时模板（供「导出为独立 EXE」使用）
5. 查看环境信息（版本 / 依赖 / 模板新鲜度 / OCR 运行时）
6. 退出
```

首次选 `1` 会自动创建 `.venv`、按 `requirements.txt` 安装依赖，并预取 OCR 模型（约 180MB，需联网，几分钟）。之后每次启动都是秒开。

### 命令行方式

```bat
start.cmd dev             :: 直接启动编辑器
start.cmd deps            :: 只检查 / 安装依赖
start.cmd build           :: 打包发布版
start.cmd build-runtime   :: 只重打运行时模板
start.cmd ocr-runtime     :: 准备 OCR 运行时（库 + 模型）
start.cmd env             :: 查看环境信息与模板新鲜度

:: 追加 --force 强制重装依赖，--yes 跳过交互（等价菜单默认项 1）
```

### 完全手动方式

不想用启动器的话，也可以自己来：

```bat
py -3 -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe src\blueprint_app.py
```

> ⚠️ **依赖版本被刻意钉死**：`PySide6==6.9.3` 和 `paddlepaddle==3.2.2` 不能随意升级，两者在更高版本上分别有 Qt 包装器崩溃和 oneDNN 推理回归问题。原因都写在 `requirements.txt` 的注释里。

## 📦 打包与导出

项目有两层打包，概念别搞混：

| 产物 | 命令 | 作用 |
|------|------|------|
| **发布版编辑器** | `start.cmd build` | 把编辑器本身打成 `dist\BlueprintAutomation\`（onedir），可脱离源码分发 |
| **运行时模板** | `start.cmd build-runtime` | 生成 `BlueprintRuntime.exe`，是**导出 EXE 的底座**，每次改动 `src/blueprint/runtime/` 后都要重打 |

**导出蓝图成独立 EXE**：在编辑器里打开蓝图 → 点工具栏 **📦 导出 EXE** → 确认资源清单 → 开始导出。

导出前会自动体检，拦截「组件引用断链」「OCR 运行时缺失」「运行时模板过期」三类坑。产物自带执行引擎，并把蓝图引用的图片资源一起打包，运行时不再依赖原工程目录。

> 打包需要 PyInstaller，`bp_dev.py` 会在首次打包时自动安装。

## 🛠 技术栈

- **界面**：PySide6 / Qt（QGraphicsScene 自绘节点画布）
- **图像**：OpenCV（模板匹配，Qflow 评分）、Pillow、NumPy
- **OCR**：PaddleOCR + PaddlePaddle，可选 ONNX Runtime 推理后端（老 CPU 上约快 5 倍）
- **输入模拟**：pyautogui / pydirectinput / pynput
- **系统集成**：pywin32、psutil
- **打包**：PyInstaller（onedir）

## ❓ 常见问题

**Q：必须装 Node.js 吗？**
A：只有 `start.cmd` 启动器需要。装好 Python 依赖后直接跑 `src/blueprint_app.py` 也行。

**Q：OCR 模型会自动下载吗？**
A：会。启动器菜单 `1` / `2` 都会自动预取；也可以随时用 `start.cmd ocr-runtime` 手动准备。菜单 `5`（`env`）只做体检报告，不下载。

**Q：导出的 EXE 在别的电脑上跑不起来？**
A：检查三件事——运行时模板是否最新（`start.cmd build-runtime`）、蓝图里的组件是否断链、含「文字」节点时 `ocr_runtime/` 是否和 EXE 放在一起。导出对话框会自动体检并提示。

**Q：为什么不能升级 PySide6 / paddlepaddle？**
A：见 `requirements.txt` 中的注释，高版本分别存在 Qt 包装器崩溃与 oneDNN 推理回归，当前钉死的版本是实测最稳的组合。

更多问题见内置手册的「🐺 常见问题」章节。
