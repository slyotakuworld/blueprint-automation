# 📸 Screenshot · 截图

> 把目标窗口（或屏幕）的某个 ROI 区域截下来，输出成图像给下游用~可以直接喂给网络请求节点，把图交给别的程序处理，也能存成文件。

---

## 节点外观

- **分类**：👁 视觉感知
- **配色**：深青蓝 (#0e3a5c / #1f8dd6)
- **短名**：`screenshot`

---

## 端口

### 输入
| 名称 | 类型 | 标签 | 说明 |
|------|------|------|------|
| `in_exec` | ▶ 执行 | ▶ | 上游触发 |

### 输出
| 名称 | 类型 | 标签 | 说明 |
|------|------|------|------|
| `out_done` | ▶ 执行 | 完成 | 截图成功 |
| `err` | ▶ 执行 | 失败 | 截图失败 / ROI 为空 |
| `image_bgr` | ○ 数据 | 图像(BGR) | numpy 数组，直接给下游「文字识别」等节点用 |
| `image_png_bytes` | ○ 数据 | PNG字节 | PNG 编码后的字节流，可作网络请求的 body |
| `image_path` | ○ 数据 | 保存路径 | 若填了「保存路径」，这里是落盘后的文件路径，否则空字符串 |

---

## 参数一览

| 参数名 | 编辑器 | 默认值 | 说明 |
|--------|--------|--------|------|
| `capture_mode` | 下拉 | `target` | 截取范围：`target`=目标窗口 / `fullscreen`=全屏 |
| `temp_target_title` | 文本 | `""` | 窗口标题子串（仅 target 模式）；支持 `{var}` |
| `temp_target_exe` | 文本 | `""` | 程序名子串（如 notepad.exe）；支持 `{var}` |
| `temp_target_class` | 文本 | `""` | 窗口类名精确匹配；支持 `{var}` |
| `roi` | 四元组 | `(0,0,0,0)` | 相对窗口/屏幕左上角的 (x, y, w, h)；全 0 = 截整个范围。可点工具栏「🖱 框选ROI」鼠标框选 |
| `save_path` | 文本 | `""` | 留空=只输出不落盘；填了就存 PNG 并输出 image_path；支持 `{var}` |

> 💡 **工具栏快捷操作**（选中截图节点时出现在属性面板上方）：
> - 🖱 **框选ROI**：鼠标拖框选一块区域，自动回填 `roi` 并显示预览图。
> - 🎯 **拾取临时窗口** / 📋 **从列表选择**（仅「目标窗口」模式）：点窗口或从列表选，自动回填 `temp_target_*`。

---

## 典型用法

### 1. 截目标窗口某个区域，发给别的程序处理
```
Screenshot(截取范围=目标窗口, 临时目标·程序名=game.exe, ROI=(100,50,200,80))
   └─ image_png_bytes ─→ HttpRequest(POST body=图片字节)
```
拿到 `image_png_bytes` 后接网络请求节点，把图发给后端识别/处理。

### 2. 截一小块存文件
```
capture_mode = target
temp_target_title = 我的窗口
roi = (10, 10, 120, 40)
save_path = C:\temp\snip.png
```
→ 截下目标窗口左上角 120×40 那块，存成 PNG，`image_path` 输出路径。

### 3. 截图喂给文字识别
```
Screenshot(ROI=血量数字区域) ── image_bgr ──→ OcrRecognize(图片来源=用输入图像)
```

## 常见问题

**Q：target 模式没找到窗口会怎样？**
→ 自动退化为全屏截图，并在日志里提示。

**Q：image_bgr 能存变量吗？**
→ 它是运行时内存对象（numpy 数组），不推荐写进变量（变量是给字符串/数字用的）。正确做法是连线传给下游节点，或先 `save_path` 落盘再用路径。
