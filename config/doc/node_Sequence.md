# 🔀 Sequence · 顺序执行

> 按顺序一条条试路径~短路模式只要一条失败就立马退出走失败口；完全模式得条条都跑完才判；一真即真只要一条成功就收工走完成；每两条之间还能歇一会儿哟。

---

## 节点外观

- **分类**：🧠 逻辑组件
- **配色**：蓝灰 (#57606A / #58A6FF)
- **短名**：`seq`

---

## 端口

### 输入
| 名称 | 类型 | 标签 | 说明 |
|------|------|------|------|
| `in_exec` | ▶ 执行 | ▶ | 上游触发 |

### 输出
每个路径是一条 ▶ 执行输出，默认 3 条路径（可动态增减）：
| 名称 | 标签 | 说明 |
|------|------|------|
| `1` | #1 | 第 1 条路径（第一个尝试） |
| `2` | #2 | 第 2 条路径 |
| `3` | #3 | 第 3 条路径 |
| `else` | 失败 | 根据模式判定为失败的出口 |
| `out_done` | 完成 | 根据模式判定为成功的出口 |

> 💡 路径数可通过 `num_paths` 参数（1 ~ 50）动态增减，对应的输出端口会自动增减。

---

## 参数一览

| 参数名 | 编辑器 | 默认值 | 必填 | 说明 |
|--------|--------|--------|------|------|
| `mode` | 下拉 | `short_circuit` | - | 求值模式（三种，见下表） |
| `num_paths` | 整数 | `3` | ✅ | 路径数量（1 ~ 50） |
| `interval_sec` | 小数 | `1.0` | - | 每条路径之间的等待秒数 |

### 三种模式详解

| mode 值 | 中文 | 含义 |
|---------|------|------|
| `short_circuit` | **短路模式 AND** | 按 #1 → #2 → #3 顺序试。任一条路径返回"失败语义"就立刻退出走 `else`；全部成功才走 `out_done`。遇到第一个失败就停。 |
| `complete` | **完全求值** | 所有路径必须都跑到"成功语义"才算通过（走 out_done）；任一条失败 → else。**无论中途成与败，所有路径都会完整跑完**，方便调试看每条都啥结果。 |
| `or_true` | **一真即真 OR** | 按顺序尝试，任一条成功 → 立刻收工走 out_done；全部失败才走 else。 |

## 典型用法

### 1. 短路模式：依次尝试 3 个位置点同一个按钮
```
Sequence：
  mode = short_circuit
  num_paths = 3
  interval_sec = 0.5

#1 → FindImage(模板A) → Mouse(点击) → 如果成功 → out_done → End
                                         如果失败 → 自动等0.5秒 → #2
#2 → FindImage(模板B) → Mouse(点击) → 同上，失败 → #3
#3 → FindImage(模板C) → Mouse(点击) → 还失败 → else → Notify("找不到按钮！")
```
→ 适合同一个按钮在 UI 里可能有 3 种颜色状态，任何一个能找到就行。

### 2. 完全求值：3 个日常任务必须都跑完
```
Sequence：
  mode = complete
  num_paths = 3
  interval_sec = 2

#1 → 签到任务链路 → 成功/失败都继续跑#2
#2 → 领取奖励链路 → 成功/失败都继续跑#3
#3 → 发送邮件链路 → 三条都跑完全 → out_done / else
```
→ 三条互不影响，某一条失败不会打断其他条。

### 3. 一真即真：3 个入口哪个能进就走哪个
```
Sequence：
  mode = or_true
  num_paths = 3
#1 → FindImage("活动入口A") → 找到了 → 立即 out_done
#2 → FindImage("活动入口B") → #1失败才试#2
#3 → FindImage("活动入口C") → 三条都找不到 → else
```

## 什么算"成功语义 / 失败语义"？

一个路径的末尾节点如果有：
- **两个执行输出**（比如 FindImage 有 found/not_found，Mouse 有 done/err，Command 有 done/err）→ 走 **✓ done/success/found 那一条 = 成功语义**；走 **✗ err/fail/not_found = 失败语义**
- **只有一个执行输出**（Wait、PressKey、SetVariable 等）→ 只要跑完就算成功语义

## 常见问题

**Q：每条路径是并行跑吗？**
→ 不是，严格按 #1 → #2 → #3 顺序一条一条跑。需要并行的场景目前不支持（也用得少）。

**Q：每条路径内部的执行失败了，怎么告诉 Sequence？**
→ 路径末尾节点的失败分支，比如 Mouse.err，一定要**悬空不接**就行。Sequence 靠连接关系自动感知：走到某个节点的"失败出口"且下游没有连线 = 这条路径失败语义。如果 Mouse.err 你接了个 Notify 然后继续接到下一个节点 = Sequence 会认为这条路径还在执行，不判失败！
